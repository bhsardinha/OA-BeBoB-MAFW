## 1. Observations (cited)

1. **`[dev+0x268]` is `m_audio_b_FWAVCUnit`** (object 0xf8 B, created in `AllocateConnectionManager @0x23c72`): a private copy of `IOFireWireAVCUnit`. Its vtable (read from the data, `VtDump2.java`): `0x8a8` = `AVCCommandExtendedTimeout @0x1594`, `0x8b0` = `AVCCommand @0x17fc` (async), **`0x8b8` = `AVCCommandWithErrorResponse @0x1508`**. So every `vt[0x8b8]` call in the device (Rev1 plug-signal format, `AVCVendorCommand` HSCI frame) is the retrying, error-checked synchronous command, not a raw send. The previously cited `vt[0x8b0]` for the selector command is the *async* `AVCCommand`.
2. `AVCCommandExtendedTimeout`: `1 <= len <= 0x200` else `IOLog("Loopy AVCCmd, len %u, respLen %u")` + `0xE00002C2`; `IOFireWireAVCCommand::withNub(nub, cmd, len, resp, &respLen)`; command timeout field set to **1,000,000 µs**; `submit(false)`; one command at a time (lock `[+0x98]`).
3. `AVCCommandWithErrorResponse`: calls `0x8a8`; while the result is `0xE0008014` (bus reset): `IOSleep(1000)`, retry, at most 25 retries (`0x19 < n` break); then `CheckAVCError`.
4. `CheckAVCError @0x14b6` (only when the IOReturn is 0, looks at `resp[0]`): `0x08` → `0xE00002C7` (NOT IMPLEMENTED); `0x0A` → `0xE00002C2` (REJECTED); `0x0F` (INTERIM) → `IOSleep(500)`; any value outside `0x08..0x0F` → `IOSleep(1000)`; other `0x09..0x0E` → return immediately.
5. `FWRev1AudioDevice::AVCControlPlugSignalFormat @0x13734`: 8-byte frame `00 FF (0x18|dir!=0) plug 90 FDF FF FF` through `0x8b8` with an 8-byte response buffer; result discarded by `ConnectAudioMIDIChannels`. (Bytes were already in Q3a §3 Correction; the call target is new.)
6. **`ConnectAudioMIDIChannels @0x12156`** (decomp `FWEngine2__ConnectAudioMIDIChannels.c`): `[+0x348]==0` → first kick INPUT, sleep 500; then TX program `vt[0x120]` = `Connect(0)`; sleep 500; kick (`[+0x348]==0` → OUTPUT `0x18`, else INPUT `0x19`); sleep 500; RX `Connect(0)`; success → (`[+0x348]!=0`) kick OUTPUT `0x18`; failure → TX `Disconnect` (`vt[0x128]`). For the FW1814 (`[+0x348] = 1`): **TX Connect → 500 ms → INPUT 0x19 → 500 ms → RX Connect → OUTPUT 0x18**. This confirms the Q3a Correction (INPUT then OUTPUT, 500 ms apart) and shows the "start TX/RX program" there is `Connect`; the DCL `Start` is separate (Q-START).
7. **Channel wiring (`CreateIsochChannelAndPorts @0x255c2`, slots read from the `m_audio_b_FWIsochChannel` vtable):** `0x128` = `IOFWIsochChannel::init`, `0x138` = `m_audio_b_FWIsochChannel::setTalker`, `0x140` = `IOFWIsochChannel::addListener`, `0x148` = `allocateChannel`. The call order in the decompile is `vt[0x138](local DCL port)` then `vt[0x140](FWRemoteIsochPort)`: **the LOCAL DCL port is the channel's TALKER and the REMOTE port is its LISTENER, for both TX and RX.** This also explains `AdjustOutputDCL`: `*(channel+0x28)` is `IOFWIsochChannel::fTalker` = the local DCL port, the object that receives `notify(kFWDCLModifyNotification)`.
8. `FWRemoteIsochPort`: `init(mgr, flag, plug)` stores `[+0x10]/[+0x18]/[+0x1c]`; `getSupported` = speed `0x7fffffff`, channels all ones; `allocatePort(speed, chan)` = `mgr->vt[0x120]` `Connect(bool = (flag==0), chan, plug)`; `releasePort` = `mgr->vt[0x128]` `Disconnect`; `start`/`stop` return 0. The program stores `flag = !talking`, so `Connect(true, …)` is the **TX** case.
9. `FWAVCConnectionManager` vtable (data): `0x118` InitWithDevice, `0x120` Connect, `0x128` Disconnect, `0x130` BusReset, `0x138/0x140` SystemWillSleep/WokeUp (empty), `0x148` makeP2PInputConnection, `0x150` breakP2PInput, `0x158` makeP2POutputConnection, `0x160` breakP2POutput, `0x168` ReconnectP2P, `0x170` updateP2PCount, `0x178` makeConnection, `0x180` breakConnection. `Connect(true, chan, plug)` → `Connect_iPCR(plug, chan)` (asm `0x248d7`: `esi = ecx`, `edx` = channel unchanged); `Connect(false, …)` → `vt[0x158](this, plug, chan)` (asm `0x248e9`).
10. `Connect_iPCR @0x247ba`: `IOFireWirePCRSpace::getPCRAddressSpace(bus)`; allocate a plug into `plugs[plug]` (3 entries at `[+0x2c]`, count `[+0x28] = 3`; an out-of-range index falls back to element 0) with the callback `HandlePCRLock @0x23f26` (**an empty function**); read it; write `ch << 16 | 0xC1003C7A`; then `vt[0x148]` `makeP2PInputConnection(plug, ch)`. `Disconnect_iPCR @0x246ba`: `breakP2PInput(plug)`, then read/write the host plug with `0x7a` and free it.
11. `makeP2P{Input,Output}Connection` / `breakP2P*`: `device->vt[0x688]()` (the device's work loop) `->vt[0x1a0]` = `IOWorkLoop::runAction(Core…, this, plug, channel, 0, 0)`. `CoreMakeP2POutputConnection @0x23f86` → `makeConnection(0xF0000904 + 4·plug, channel, nub->FWSpeed())`; `CoreMakeP2PInputConnection @0x23f50` → `makeConnection(0xF0000984 + 4·plug, channel, 0x80000000)`; breaks → `breakConnection(addr)`.
12. `makeConnection @0x24980`: creates `OSArray` (capacity 4) on first use, `updateP2PCount(addr, +1, failOnReset = 0, channel, speed)` through `vt[0x170]`, and on success stores an `FWP2PConnection {+0xc addr, +0x10 channel}`. `breakConnection @0x24454` finds the record by address, `updateP2PCount(addr, 0, …, 0xffffffff, 0x80000000)`, removes it; errors `0xE00002BE` (no array) / `0xE00002F0` (not found). `free @0x23e96` breaks all records.
13. `updateP2PCount @0x244f0` details beyond Q-CMP-connect §3: the new value is recomputed from the **first read** on every attempt while the compare value is the previous attempt's returned old value; a status other than `0xE0008014` with `locked == false` also sleeps 100 ms and retries; after 4 attempts the **last status is returned (0 when every attempt was "success, not locked")** — the reference can report success without having locked.
14. `ReconnectP2P @0x24176`: `IOSleep(0x44c = 1100)`, replay each record with `failOnReset = 1`, channel from the record, speed unchanged, stop on `0xE0008020`, then `[[dev]+0xe8]->vt[0xcb0]` (engine notification). `BusReset @0x24216`: retain array and device, `InvokeOnNewThread(ReconnectP2PThread)`.
15. `ForceStopNotificationProc @0x25766`: `IOLog("M-FW: channel %p force stop proc (reason:%X)")`, `program[+0x8d] = 0`. `FWDCLProgram::Disconnect @0x250a2`: `channel->releaseChannel()` (`vt[0x150]`), release, clear `[+0x58]` and `[+0x8c]`. `ResetPort @0x2541a` per `Q-MB-dcl-callbacks.md` §6, args now read: TX `startState = cycleTime`, `startMask = 0x7fff000`; RX `startState = cycleTime >> 12`, `startMask = 0x7fff`; `chan->setTalker(newPort)`, `port->allocatePort(speed, chan+0x4c)`.
16. `SufficientBandwidthAvailable @0x22e8` = `GetBandwidthBytesAtSampleRate < 0x186b`; `ConnectAllPlugs @0x12476` returns `0xE00002BC` when already connected, `0xE00002BE` when the check fails, else `ConnectAudioMIDIChannels`; `DisconnectAllPlugs @0x11bfa` disconnects RX then TX.

## 2. Corrections this item forces

* `Q-CMP-connect.md` §1 (and `C4` §2.1 pseudo-code): "`chan->addListener(local)`, `chan->setTalker(remote)`" is **reversed**; local = talker, remote = listener (obs. 7).
* `Q3a` / `C2` §7 / `C4` §2.4: the INPUT-then-OUTPUT order stands; "start TX/RX program" in those steps is `Connect`.
* `Q6` / `C3` §2: `[+0x268]` is the FWAVCUnit, not `FWHSCI`; the HSCI frame goes through `AVCCommandWithErrorResponse` (so it is subject to the 25-retry/bus-reset loop and the post-command pauses of obs. 3-4). `Q5` line 270's "`FWHSCI *hsci = this->fHSCI; // [+0x268]`" is wrong.

## 4. Open / unverified

* **Host PCR plug family.** The reference calls `PCRSpace` vtable slots `0x1b8/0x1c0/0x1c8/0x1d0` (allocate/free/read/update). The clone uses the **output-plug** methods because the written value (`0xC1003C7A`: overhead-ID and payload fields) only exists in an oPCR layout — an **inference**; check by comparing the slot indices with `IOFireWirePCRSpace`'s vtable in IOFireWireAVC 4.2.6 on the build PC.
* The meaning of the fixed payload `0x7A` (122 quadlets) is still unverified (Q-CMP-connect).
* The single `fSerial` lock replaces the reference's two locks (`[+0x98]` command, `[+0xd0]` current-command pointer); the second protects an abort path (`stop`) the clone does not have yet.
* ~~`AVCCommand @0x17fc` (async queue, `FinishAsyncCommand`) and `updateSubUnits` are not ported; no M-C step uses them.~~ **Wrong (Correction 2026-10-17):** selector, feature-block and mixer-connect commands use the async queue; ported 2026-10-17.
* Who calls `ResetPort` for `FWEngine2`: only `FWBaseEngine::StartAudio @0x4bca` was found (Q-START obs. 9); whether `FWEngine2` ever calls it is unverified.
* The engine hook after reconnect (`[[dev]+0xe8]->vt[0xcb0]`) is a callback pointer in the clone until M-D/M-J.
* `IOCreateThread` (deprecated but present in the 10.13 KPI) stands in for `UKernelCallHelpers::InvokeOnNewThread`; thread behaviour on 10.13.6 is untested.
* Nothing here has run: acceptance (device locks, isoch both ways, 5 min stable) is the integrated hardware run.
