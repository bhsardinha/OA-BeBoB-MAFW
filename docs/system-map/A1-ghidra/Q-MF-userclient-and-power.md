# Q-MF — user client port (M-F) and device power hooks (M-E2) (2026-10-15)

Bundle `_extracted/` v1.11.2 kext, Ghidra 12.1.4 (`decomp_by_name.sh`), builds on `Q-UC-surface.md` (selectors, meter page, notification layout — all re-checked against the decompiles, no change) and `Q-ME-mixer-property-framework.md`. Raw decompiles: `FWKIPCUserClient__*.c`, `FWUserClient__*.c`, `FWPropertyDict__{Cache*,Send*}*.c`, `FWAudioDevice__{performPowerStateChange,WakeAfterSleep,message}.c`, `FWAVCAudioDevice__System*.c`.

## Observations (cited)
1. **User-client registry** (`FWKIPCUserClient::UserClientAdded @0x1620c` / `UserClientRemoved @0x15bea` / `UserClients @0x15bdc`): a static `OSSet` of every client, created at the first add, released when empty. The property dictionary visits only clients whose provider (`this+0xd8`) equals its device (`FWPropertyDict__CacheModifiedPropertyDictionaryInUserClients.c`, `...SendPropertyChangedMessagesToUserClients.c`).
2. **Property-change delivery** is two-step: `ApplyModifiedProperties` calls `CacheModifiedPropertyDictionaryInUserClients(queue)` → each client's `AddModifiedProperties` (virtual `0x960`) merges the entries into its private pending dictionary (lazily created with a recursive lock; counter `[+0x118]` incremented per call); after the setters ran, `SendPropertyChangedMessagesToUserClients` → `SendChangedPropertiesMessage @0x1602a`: `SerializeModifiedProperties @0x15cba` (OSSerialize capacity 0x200, XML, pending set flushed, IOBMD of `len + 0x2c`), template copied over the first 0x2c bytes, `msgh_size` = total, type field 0, `mach_msg_send_from_kernel_proper`. `SendArbitraryPropertyToUserClients` (one-entry dictionary) and `SendAllPropertiesToUserClients` (`CopyAllProperties`) only cache and poke the work loop, so they are delivered by the next `checkForWork` that finds the queue object (reference behaviour).
3. **Type 0 registration** accepts only type 0, otherwise `IOLog("M-FW: Someone registered for an unknown message type:%X")` and `0xE00002C2` (`FWKIPCUserClient__registerNotificationPort.c`). **`message() @0x15fca`** forwards every IOKit message to the registered port with the code in the type field, then the superclass.
4. **FWUserClient (`com_m_audio_FWUserClient`)**: `start` requires the provider to be an `FWAudioDevice` (`[+0x290]`); selectors `500..507` map to `sMethods` (Q-UC-surface §2, bytes re-read); MIDI selectors run on the device work loop (`provider->getWorkLoop()->runAction(ActionStartMIDI/StopMIDI/SendMIDI, engine, …)`, `0xE00002D8` when there is no work loop); `CoreStartMIDI @0x717c` remembers a start request while the engine is paused (`[+0x234] > 0`, flag `[+0x230]`) else `vt[0xcf0]` `StartMIDI`; `CoreStopMIDI @0x714a` clears the flag when MIDI is not running (`[+0x298]`) else `vt[0xd00]` `StopMIDIAndClearBuffers`. `SetInitializedProperty` sets the device property `MADeviceInitialized = true`. `EntryDiceSet/Get` return `0xE00002C7`. `FWEngineUserClient` (returned by the engine's `createUserClient @0x5fa2`) is an empty subclass of `IOAudioEngineUserClient` (constructor only changes the vtable) — not reproduced, the stock class is equivalent.
5. **Power** — `FWAudioDevice::performPowerStateChange @0x1e96`: `*us = 0`; old==0 && new>0 → `[+0x259] = 1` (woke from sleep); old>0 && new==0 → `vt[0xb18]` = `SystemWillSleep`. `WakeAfterSleep @0x1e7c` is a tail call to `vt[0xb10]` = `SystemWokeUp`. `FWAudioDevice::message @0x3344` (Q-ME §4) runs `WakeAfterSleep` on a new thread when the resume message arrives with `[+0x259]` set, then calls the connection manager's `vt[0x140]` (= `FWConnectionManager::SystemWokeUp`, an empty base function — vtable dump) and clears the flag. `SystemWillSleep @0x22b16` / `SystemWokeUp @0x22d76` as in Q-ME §7b; their `vt[0xb88]`/`vt[0xb90]` are `Pause/ResumeReceptionOfControlPackets`.

## Clone mapping
`FWKIPCUserClient.{h,cpp}`, `FW1814UserClient.{h,cpp}` (Info.plist FW1814 personality gets `IOUserClientClass = com_openaudio_FW1814UserClient`), `FWPropertyDict` delivery functions, engine `UserStartMIDI/UserStopMIDI/SendMIDI/MidiPortMemory` (the last two are M-H stubs returning unsupported), `FWAudioDevice::performPowerStateChange`, `FWAVCAudioDevice::SystemWillSleep/SystemWokeUp`, thread hop via `FWRunOnNewThread`.

## Deviations (kept visible in code)
* `clientClose` also calls `terminate()` (the reference leaks the client, Q-UC Correction R16). Risk: none known; if a panel relies on the client surviving `clientClose` it would have seen the leak as a bug.
* `WaitForTermination` waits on an `IOLock` condition instead of a Mach semaphore (no semaphore KPI dependency).
* The registry set is lock protected (reference: unlocked); `SerializeModifiedProperties` returns NULL when nothing is pending (reference would resend its previous buffer).
