2. **Format offer:** `SetStreamFormat @0x4192` (after the PCM formats of the output stream only, and only while `[+0x2d0]` external sync is off and the device `SupportsAC3`) calls `AddAC3Format @0x39a0`: format {2 ch, `'cac3'`, `'sint'`, 16 bit in 16, alignment 0, **little-endian**, **not mixable**} with extension {version 1, flags 0, frames per packet `0x600`, bytes per packet `0x1800`} at 48000, 44100 and 96000 Hz.
3. **Enter / leave:** `PerformFormatChange` (M-D) decides by the `'cac3'` tag. `EnableAC3Format @0x445e`: only when `[+0x2d4] == 0` and the audio is not started (`[+0x238] == 0`): connected → `DisconnectAllPlugs`, pending `|= 0x8000`; `[+0x2d4] = 1`; `[+0x2ec]` (output stream channels) `= 2`; pending `|= 0x270000`; device `AC3Activated(true)`. `DisableAC3Format @0x596a`: reverse — plugs down, `[+0x2d4] = 0`, `[+0x2ec]` := the DeviceChannels `outStream`, `ResetSampleBuffers`, `UpdateDCLProgramsWithNewPacketSizes`, plugs up, `AC3Activated(false)`.
4. **Transport:** `StartAudio` (Q-START) calls `StartAC3Output @0x1185e` in AC3 mode: `StopMIDI` if MIDI runs, then `ActivateAC3Output @0x11fee` = `SetAC3OutputState(true)` + `ActivatePCMOutput` (TX program only — `ActivatePCMInput` refuses in AC3 mode); `StopAudio` calls `DeactivateAC3Output @0x11fc6` = `DeactivatePCMOutput` + `SetAC3OutputState(false)`. `SetAC3OutputState @0x11f28` does nothing unless `WantsAC3MixerBypass()` — **never on the FW1814** (the other branch sends an AV/C vendor frame and a selector through a function-block map whose type 9 is an error on the FW1814).
5. **Clip:** `ClipOutputSamplesWithMixPtrAdjusted @0x40aa`: output stream format `'cac3'` → `ClipAC3Output` only if `[+0x2d4]` and ≤ `0x600` frames. `ClipAC3Output @0x11c44`: error unless stream bytes `[+0x2d8] ≥ (first+num)·4`, format not mixable, 2 channels, `first+num ≤ 0x2000`, buffers non-NULL. Then `LocalRearrangeSampleFrame16Bit2` builds, per frame, a data block of `outChannels (+0x2e0) + midi (+0x2e8)` quadlets in the scratch: audio quadlets `0x40`, the two S/PDIF quadlets `((w&0xff)<<16 | (w&0xff00)) + 0x40` (memory bytes `40 hi lo 00` = AM824 label + 16-bit sample MSB first), MIDI quadlets `0x80`; finally the blocks are `memcpy`ed into the TX packets with the same per-packet loop as the PCM clip. The `_RearrangeSampleFrame16Bit2` asm routine (stride 4, `0x40000000` constants) is the Audiophile-class twin and is not used on the FW1814.
