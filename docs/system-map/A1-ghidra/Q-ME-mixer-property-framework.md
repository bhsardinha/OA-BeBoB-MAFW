## 1. Property framework

* `FWPropertyDict` (`m_audio_b_FWPropertyDict`, an `IOEventSource`): `[+0x48]` device, `[+0x50]` `OSSet` of **immediate** keys, `[+0x58]` `OSDictionary` of queued (modified) values, `[+0x60]` `OSDictionary` key→property (all installed props), `[+0x68]` the device work loop (`init` @a… adds itself as an event source: workloop `vt[0x140]`), `[+0x70]` re-entrancy flag (`OSCompareAndSwap(0,1)`), `[+0x78]` `OSSet` of props with pending audio-control updates.
* `InstallProperty(prop)`: `[+0x60].setObject(prop.key[+0x18], prop)`; if `prop[+0x28]` (immediate flag, set only by `FWFunctionProp::init`) → add key to the immediate set; `prop[+0x20] = dict`.
* `SetProperties(obj)` (the device's `setProperties`): `OSDictionary` → for each key `SetOneProperty(key, value)`; an `OSString` → `SetOneProperty(sym, NULL)`; anything else → `0xE00002C2`; then `signalWorkAvailable`. `SetOneProperty`: key in the immediate set → `prop->CallSetter(key, value)` (vt `0x128`) **synchronously**; otherwise `ModifyProperty` (queue, replacing any older value).
* `checkForWork`: `CheckAudioControlUpdates`; `CheckModifiedProperties(true)`; if the queue is still non-empty → signal again. `CheckModifiedProperties(notify)`: if the queue exists → `ApplyModifiedProperties(notify)` + `SendPropertyChangedMessagesToUserClients` (M-F). `ApplyModifiedProperties`: reentrancy guard; `CacheModifiedPropertyDictionaryInUserClients(queue)` (M-F); for each queued key: no installed prop → drop it; else remove it from the queue, `CallSetter(key,value)`, and when it returned 0 and `notify` → `prop->NotifyAudioControlsOfChange()`.
* `InjectModifiedProperty(key, value, flag)` (used by audio-control callbacks): only if workloop `vt[0x138]` (= `inGate`/on-work-loop test, **unverified name**) is true: `ModifyProperty` + `CheckModifiedProperties(flag)`. `SetPropertyAndNotifyUserClients(key, value)` = `ModifyProperty` + `signalWorkAvailable`.
* `CopyProperty(key)`: installed prop → `CallGetter(key, &out)`; `"MAMetaAllProperties"` → `CopyAllProperties` (dictionary of every prop's getter output). `getProperty`/`copyProperty` of the device first try `HandleDigiHandshakeProperty(key)` (§7), then `CopyProperty`, then super. The reference's `getProperty` leaks one reference per call (it retains in `CopyProperty` and releases once); the clone must not.
* `setProperties` of `FWAVCAudioDevice`: if the dictionary has `"MASampleRate"` (OSNumber) and it differs from the engine rate `[engine+0x8c]` → **synchronously** `vt[0xa78]` = `RequestFormatUpdateForSampleRate(rate)` before the generic dispatch.
* Property kinds (`m_audio_b_FW*Prop`, base `FWBaseProp`: `[+0x10]` ?, `[+0x18]` key `OSSymbol`, `[+0x20]` dict, `[+0x28]` immediate flag): `FW32BitNumberProp` (value `[+0x2c]`, setter functor `[+0x38]`; `CallSetter` requires an `OSNumber`, calls the functor first and stores the value only if it returned 0; getter → `OSNumber(value, 32)`), `FW64BitNumberProp` (value `[+0x30]`, functor `[+0x40]`), `FWFunctionProp` (functor `[+0x38]` called with the raw `OSObject*`; immediate), `FWBaseArrayProp` (`[+0x2c]` n, `[+0x38]` per-element functor `(index+1, value)`, `[+0x48]` "all changed" functor, `[+0x50]` `uint32[n]`; setter: `OSArrayToSeriatimValues` (elements must be `OSNumber`, count clamped to n; each `Set32BitValueFromArrayElement(i, v)` stores and calls the per-element functor with `(i+1, v)`) then the `[+0x48]` functor; getter: `OSArray` of `OSNumber(…,32)`), `FWChannelGroupProperty` (array prop whose element storage is a field of the channel group: `[+0x60]` group, `[+0x68]` byte offset of the field in the 0x20-byte channel slot, `[+0x70]` optional second group; element get = 32-bit read at `slot+offset`; element set = `int32(int16(v))` at `slot+offset`; `CallSetter` snapshots `AdjustedLevels` of both groups, sets the values, then calls each group's `vt[0x28]` (= `SendLevelsToDevice(before)`; `before` is unused in the body — **no delta logic**, every channel is resent).
* `ChannelGroupProperty` field offsets: Levels `+0`, balance `+4`, Mute `+8`, Solo `+0x10`, Link `+0x18` (64-bit cells; only the low 32 bits are written).

## 2. Channel groups

* `BaseChannelGroup` (vtable: `+0x10` `Count()`, `+0x18` `ChannelAtIndex(i)`, `+0x28` `SendLevelsToDevice(before)`): `[+8]` parent group (self if NULL — used by `Solo()`), `[+0x10]` dim, `[+0x11]` mute-all, `[+0x12]` enabled, `[+0x14]` min level (`0xffffff01` = −255), `[+0x18]` max level (0), `[+0x20/0x28]` per-channel functor `(index+1, adjusted level)`, `[+0x30/0x38]` batch functor `(register offset, nQuads, int16 BE buffer)`, `[+0x40]` register byte offset, `[+0x44]` multiplier (`0x80`, set by `SetupBatchChangeMethod @0xe184`).
* Channel slot (0x20 B): `+0` level, `+4` balance, `+8` mute, `+0x10` solo, `+0x18` link. `ConcreteChannelGroup<N>`: slots at `+0x48 + i*0x20`; `ChannelAtIndex(i≥N)` returns slot 0 (clamp).
* `AdjustedLevelForChannel(ch, anySolo, muteAll, dim)`: `muteAll || (anySolo && ch.solo==0)` → min; else (`ch.mute==0`) `clamp(ch.level + ch.balance, min, max)` and (`ch.mute!=0`) → min; `dim` → `max(level − 0x14, min)` (0x14 = 10 dB at 0.5 dB/unit). `Solo()` = any channel in the **parent** group has solo ≠ 0. `AdjustedAndMultipliedLevels` = `int16(adjusted * int16(multiplier))`.
* `SendLevelsToDevice`: batch functor present → `buf = AdjustedAndMultipliedLevels`, each int16 byte-swapped (big-endian), call `batch(group[+0x40], Count()>>1, buf)`; else per-channel functor with `(i+1, adjusted)`.
* `GroupChannelGroup`: union of up to three groups (`Init` sets each member's `[+8]` parent to the union); `Count` = sum; `ChannelAtIndex` walks the members; `SendLevelsToDevice` calls the members.
* FW1814 groups (`com_m_audio_FW1814Device::$_667::$_667 @0xd442`, device offsets): `+0x1318` `<4>` Output, `+0x13e0` `<18>` Input, `+0x1668` `<4>` SW-return, `+0x1730` `<4>` Headphone, `+0x17f8` `<22>` Aux send, `+0x1b00` `<2>` Aux output. Registers (`SetupBatchChangeMethod` arguments, `InitializeUserSettableProperties @0xe6ca`): SW-return `0x00`, Output `0x08`, Input `0x10`, Headphone `0x38`, **Aux output (`0x1b00`) `0x34`** with the ordinary writer, and the **Aux send group (`0x17f8`)**: the code stores `0x64` at `this+0x1838` (= group `[+0x40]`) and `0x80` at `this+0x183c` (`[+0x44]`) and installs `CustomMixerWriteWithRotatedAuxChannels` at `this+0x1830` (= group `[+0x38]`) — i.e. register `0x64`, 11 quadlets, rotated writer. **Correction to Q15f's table:** it attached the rotated writer to `this+0x1b00`; the rotated writer and register `0x64` belong to the aux-send group `0x17f8` (stores at `0x1830/0x1838/0x183c`), the aux-output group `0x1b00` is an ordinary `0x34` group.

## 3. Settings classes (key names are literal `OSSymbol` strings)

* `FWSettingsLevels::Init(dev, swReturn, output, input, headphone, auxOut)` — groups `[+0x8b0 / 0x8b8 / 0x8c0 / 0x8c8]`; each non-NULL group gets min `0xffffff01`, max `0`, a per-channel functor and the properties `MA{SWReturn,Output,Input,Headphone}{Levels,Mute,Solo,Link}` (`InitGroupProp`: Levels field 0, Mute 8, Solo 0x10 [only if the flag is set; Headphone has none; Input's Solo takes the SW-return group as second group, Output/SWReturn's second group is NULL / Input respectively], Link 0x18), `MASWReturnRoutingV2` (n = SWReturn.Count()/2 = 2, functor `SetSWReturnRouting`), `MAInputPan2` (n = Input.Count() = 18, `SetInputPan`), `MAInputRoutingV2` (n = 9, `SetInputRouting`), `MADirectMonitoringActive` (32 bit, value starts at 1), `MAGlobalDim`, `MAGlobalMute`; two `GroupChannelGroup` unions (`[+0x8d0]` SW-return+Input, `[+0x930]` Output+auxOut+Headphone).
* `SetGlobalMute(v)` / `SetGlobalDim(v)`: store, set `[Output group +0x11]` / `+0x10`, `SendLevelsToDevice`. `SetDirectMonitoringActive`: value := 1, clear Input's mute-all, send. `ResetToFactorySettings`: unions reset (levels 0, balance 0, mute/solo/link 0), Input pan array `{0xffffff01, 0xff}` pairs, routing array 0, SW-return routing `1<<i`, direct monitoring 1.
* `FWSettingsLevels::SendToDevice`: unions' `SendLevelsToDevice` (if enabled), headphone group, then input pans (`Get(i)` → pan functor `(i+1, v)` for 0..3 — **the first four only** — and routing array via `[+0x9c8]`) and SW-return routing; i.e. the pan/routing arrays are resent through their functors.
* `FWSettingsAuxSend::Init(dev, auxSend, auxOut, nMonitor)`: `MAAuxSendLevels` (aux-send group), `MAAuxOutputLevels`/`MAAuxOutputMute`/`MAAuxOutputLink` (aux-out group, fields 0/8/0x18), arrays `MAAuxOutputPan2` (n = auxOut.Count()) and `MAMonitorAuxOnOutput` (n = nMonitor = Output.Count()/2+1 = 3). Factory: all aux channels `0xffffff01`, pan `{0xffffff01, 0xff}`, monitor array 0.
* `FWSettingsRotaryControl` (`MARotaryControlV2` 64-bit, `MAMetaVirtualRotateDataKnob` function): a 64-bit mask `[+0x68]` (factory `0xffff00000000`) selects which channels the physical knob drives; `UserRotatedHardwareKnob(delta)` applies `SetLevelsFromKnob` to the `MASWReturnLevels` (bit offset 0), `MAOutputLevels` (0x20), `MAInputLevels` (0x10), `MAHeadphoneLevels` (0x38) and `MAAuxOutputLevels` (0x32) arrays through `AdjustOSNumberElement` (step: +1/−1 per detent, ×12 when the level is already below −12 and stays below; clamp −0x100..0, floor −0x80 for the single-step case).
* `FWSettingsABSwitch` (A/B button and headphone selector): `MAMomentarySwitchRoutings` (array 4), `MAHeadphoneSourceV2`, `MAHeadphoneSecondSource`, `MAMomentarySwitchSource`, `MAMomentarySwitchLatent`; `UpdateLEDs` → `AVCControlSetLEDStatus(1|2|3|0)`; `MomentarySwitchPressed` toggles A/B and re-sends; `SendMixerSettingsForCurrentMomentaryMode` rewrites `MAInputRoutingV2[0..1]` (clear/set bit 0 and 0x12) and the headphone source.
* Device-level (`m_audio_b_FWAudioDevice::InitializeUserSettableProperties`): `GUID` static property, then a dict `[+0xf8]` with `MAEnableStereoPairEngines`, `MAEnableAggregateEngine` (setter returns `0xE00002C7`), `MAMetaResetToFactorySettings` (function → `ResetMixer` @0x2660: device `vt[0xb08]` = `ResetToFactorySettings`, `vt[0xb00]` = `ResendCurrentMixerSettings` (both read from the FW1814 vtable dump), then `SendAllPropertiesToUserClients`), `MADeviceUserLabel` (function → `SetDeviceLabel` + notify); the AVC level adds `MAFirmwareInfo` (static, 0x50 bytes) and `MAClockSource` (32 bit prop **whose value cell is `device[+0x144]`**, setter `SetClockSource`).

## 4. FW1814 mixer register writes (device methods)

* `CustomMixerWriteQuads(off, n, buf)` @0x22c7a: async block write, `n*4` bytes, to `0xFFC7:0x00700000 + off` (Q15f stands). Shadow quadlets in the device: `+0x12b8…` pan shorts (`SetInputPan`: channel `1..18`, value `v = (−param)`: `short = ((−p >> 1) & 0xff) + (short)p * −0x8000`; written at register `0x3e + 2*ch` (odd channel: the short at its own index; even: index−1 — the pair shares a quadlet)), `+0x1308` input routing (register `0x90`), `+0x1310` headphone selector (register `0x98`), `+0x1314` aux monitor (register `0x9c`). `SetInputRouting(ch 1..9, bits)`: bit tests as decompiled in `FW1814Device__SetInputRouting.c` (ch 1-4: wire bits `ch−1` and `ch+3`; ch 5: wire bits 16/17; ch 6-9: bits `ch+2` / `ch+6`; each on `bswap32(1<<n)` so the shadow is already big-endian). `SetAuxMonitor(bus, on)`: bit `bus−1` of `bswap32(1<<(bus−1))` into `+0x1314`, write `0x9c`. `SetHeadphoneSelector(pair, which)`: bits `0x100<<which` / `0x1000000<<which` into `+0x1310`, write `0x98`.
* `SetClockSource` (`FWAVCAudioDevice` @0x23858): pauses the engine (`engine vt[0xa50]`), converts old 2-bit digital bitmaps (`0→0x40000000, 1→0x40000004, 2→0x40000001, 3→0x40000005`, logs `M-FW: Converting old digital bitmap`), calls `vt[0xb60]` (`SetClockSourceInternal(clk, blankSlate=false)`), derives `external = clk<0 ? (clk&0xf)!=0 : ((clk&3)−1)<2` and, when it differs from the engine's `[+0x2d0]`, calls engine `vt[0xce8]` = `FWEngine2::SetExternalSyncEnabled` (vtable dump), then `CompletePendingStateChanges`; resumes (`vt[0xa58]`).
* `FW1814Device::SetClockSourceInternal @0xe25c(clk, blank)`: pause; if the in-progress flag `[+0x1b88]` is clear: set it, `begin config change` (engine `vt[0xb00]` = `IOAudioEngine::beginConfigurationChange` (vtable dump)), build the 16-byte HSCI frame `00 FF 00 04 00 04 [sel] [clk>>3&1] [clk>>4&1] [clk>>5&1] 00×6` with `sel = {clk&3: 1→1, 2→2, 3→0, 0→3}`, send via `[+0x268]->vt[0x8b8]` (`AVCCommandWithErrorResponse`, length `0x10`), `IOSleep(300)`, store `[+0x144] = clk`, call the Rev1 base `SetClockSourceInternal` (`vt[0xb70]`, an `AVCSelectorCommand`; `clk ≥ 0x40000000` required, else `0xE00002C2`), `IOSleep(300)`, and unless `blank`: `[+0x144]=clk`, `vt[0xbe0]` (`SwitchDigitalSignals(clk)`), `FWSettingsLevels::SendToDevice`; clear the flag; `completeConfigurationChange` (engine `vt[0xb08]`); on error clear the flag and `cancelConfigurationChange` (`vt[0xb10]`). The whole body runs between engine `vt[0xa50]` = `pauseAudioEngine` and `vt[0xa58]` = `resumeAudioEngine`.
* `SetBlankSlateClockSource @0xe4f0`: `vt[0xb60]((fMode & 0x1c) + 0x40000003, true)` then `IOSleep(0x9c4)` (2500 ms).
* `SwitchDigitalSignals(clk)` @0xe5dc: `ChangeFormat`: new `DeviceChannels` row for the current rate (`vt[0xa60]`), `vt[0xc48]` (`RemoveAllSubEngines`), `SetIOFormat(row, rateIndex)`, then **sets the engine peak proc `[+0x308]`** by output-channel count: 6 → `_Sample1814PeaksSPDIF6`, 8 → `_Sample1814PeaksADAT8`, 12 → `_Sample1814PeaksADAT12`, else `_Sample1814Peaks4All`; `ClearPeakMeters`; `ResetRearrangementProcs`; `SetChannelNamesForMainEngine`; if `[+0x184]` (stereo-pair engines enabled) → `vt[0xa40]`. **Correction to Q-MD2 §3:** the FW1814 *does* use a peak proc (this one); M-D2 only ported the null case.
* `ReconnectP2P @0xe1ea`: `engine vt[0xcc0]` (`DisconnectAllPlugs`), `vt[0xcb8]` (`ConnectAllPlugs`), `IOSleep(0x44c)`, then if the engine is not in external-sync mode `SetClockSourceInternal([+0x144], blank=true)`.
* `BusReset @0xe53a`: runs the member at vtable slot `0xbf0` (= `ReconnectP2P @0xe1ea`, FW1814 vtable dump) on a **new thread** (`UKernelCallHelpers::InvokeOnNewThread`). It is called from `FWAudioDevice::message @0x3344` when, after the device is ready ([+0x258]), the message `0xE0000030` (`kIOMessageServiceIsResumed`, end of the bus reset) arrives and the device did not just wake from sleep ([+0x259] clear); otherwise a `WakeAfterSleep` thread runs. Every other message returns 0 without reaching the superclass. The base `FWAudioDevice::BusReset @0x1d3c` forwards to the connection manager (`[+0xf0]`, `vt[0x130]`); the FW1814 override replaces it.
* `AVCControlSetLEDStatus @0xdaaa(state)`: 8-byte vendor-dependent CONTROL `00 FF 00 03 00 01 [state != 1] 00` via `[+0x268]->vt[0x8b8]` (bytes confirmed in the assembly 0xdaf0..0xdb72; the vendor id bytes `03 00 01` differ from the clock frame's `04 00 04`, as read).

## 5. HSCI status poll and control packet (`m_audio_b_FWHSCI`)

* Object: `[+0x10]` nub, `[+0x18]` start refcount, `[+0x1c]` pause count, `[+0x20]` and `[+0x60]` `FWKernelTimer`s (`+0x30` points at a timer object with `vt[0x150]` start, `vt[0x158]` stop, `vt[0x160]` is-running, `vt[0x1d0]` set-delay-ms), `[+0xa0]` read command, `[+0xa8]` work loop, `[+0xb8]` callback functor, `[+0xc0]` packet size, `[+0xc8]` buffer.
* `Start(wl)` (refcounted): allocates `size/4` quadlets, creates the timer on the work loop, and (if not paused) starts it with a **50 ms** delay (`0x32`). `HSCITimerFired`: zero the buffer, `getNodeIDGeneration`, async read of `size/4` quadlets from `0xFFC7:0x00600000` (`IOFWReadQuadCommand`), callback `FWHSCIDeviceCallback`; submit failure → retry in 1000 ms. `HSCIReadComplete(status)`: error → retry 1000 ms; success → `HSCISafelyComplete` **on a new thread**: call the callback with the buffer, re-arm 50 ms. `Pause`/`Resume` stop/restart the timer by a counter; `Release` stops the timer and frees the buffer.
* `FW1814Device::StartReceptionOfControlPackets @0xe064`: size = `vt[0xba0]` (`GetControlPacketSize` = **0x58**), new `FWHSCI`, callback = `vt[0xbf8]` = `ReadHSCIData`, then `Start(workloop)`. `Stop/Pause/Resume…` also `ClearPeakMeters`. `ReadHSCIData(buf) @0xd952`: `DetectExternalSyncChanges(buf[0x14]>>24 & 1, buf[0x14]>>16 & 7)` then `vt[0xbd8]` = `ReceiveControlPacket(FW1814ControlPacketWithoutNodeID*)` @0xe9ea.
* **Packet layout (0x58 bytes), as read by `ReceiveControlPacket @0xe9ea`:** word 0 = hardware controls: rotary 0 = `(w>>24)&3`, headphone rotary 1 = `(w>>16)&3`, headphone rotary 2 = `(w>>8)&3` (`TRotaryControl::RotaryValueChanged(v)`: 1 → +step, 2 → −step, else none), `(w&3) != 0` → A/B button pressed; bytes `4..0x4f`: 19 pairs of big-endian `uint16` hardware peak values → `meters[2i], meters[2i+1]` (`[dev+0x108]`, `uint32` each); words `0x20..0x26` (bytes 0x88..0xa0 region) are the DSP/software meters copied from `[dev+0x110]` into `meters[38..51]` (with the A/B variants `[+0x1317] & 4`); word `0x14` (byte 0x50): bit 24 = clock locked, bits 16..18 = FDF. `DetectExternalSyncChanges(locked, fdf)` (§6) fires `MASampleRate` / `MARateLocked` static-property notifications.
* `[dev+0x108]` = the 52-entry `uint32` meter array that the vendor user client exposes as `clientMemoryForType(1)` (`peak[52]`, A1-Q14); `[dev+0x110]` = software-computed peaks written by the `_Sample1814Peaks*` procs.

## 6. `DetectExternalSyncChanges(locked, fdf)` @ FWAudioDevice

`[+0x25c]` last FDF; on change maps FDF → rate (0:32000, 1:44100, 2:48000, 3:88200, 4:96000, 5:176400, 6:192000; other → logs `M-FW: invalid sample rate detected (FDF:%X)%s` and uses the engine rate, FDF := 0xff) and `SetStaticPropertyAndNotifyUserClients("MASampleRate", rate)`. If `locked` and the engine FDF `[+0x228]` ≠ detected FDF, `locked := false`; on change of `[+0x25a]` → `SetStaticPropertyAndNotifyUserClients("MARateLocked", locked)`.

## 7. DigiHandshake (`LatencyProfiler<n>` property)

`getProperty`/`copyProperty` call `HandleDigiHandshakeProperty(key)`: key prefix `"LatencyProfiler"` (length in `sDigiHandshakePropertyNameStrLen`) followed by a decimal number → `DigiHandshake::Do(n)` and the result is returned as an `OSNumber`. `Do` is a 4-stage state machine over three static ints (`sStage`, `s1..s3`) using constants `0x1f31d`, `0x41a7`, `0xb14`, `0x496143`, `0x2cf535`, `0x7fffffff` (decomp `DigiHandshake__Do.c`). Purpose **unverified** (a latency-profiler tool handshake); ported for parity.

## 7b. Further findings that close open lines of Q15f / Q-P4 (this round)

* **AV/C frames (assembly + decompile, all sent through `[+0x268]->vt[0x8b0]` = async `AVCCommand @0x17fc`, response ignored):** `AVCSelectorCommand @0x23074` = 12 bytes `00 08 B8 80 <sel> 10 02 <val> 01 00 00 00`; `AVCControlFeatureFunctionBlock @0x231a8` = 12 bytes `00 08 B8 81 <fb> 10 02 <chan> <ctl> 02 <hi> <lo>`; `AVCMixerConnectSingle @0x23586` = 16 bytes `00 08 B8 82 <fb> 10 04 <b> <src> <dst> 03 02 <00 connect | 80 disconnect> 00 00 00`, `AVCMixerConnectPair @0x2367c` = singles for (2·src−1 → 2·dst−1) and (2·src → 2·dst). FW1814 mapping: clock selector = base `SetClockSourceInternal @0x23148` → selector 4, value = `clk` bit 2; aux-out pan/level = feature block 9 (`MapChannelAndFunctionBlock` case 7), control selector 3 (balance) / 2 (volume), value `(−v)<<7`; SW-return routing = `SetAVCRouting(busType 1, n=2, idx, mask)` → for each pair `i`: `AVCMixerConnectPair((mask>>i)&1, fb 1, b 0, idx, i+1)` (`MapRoutingParameters` returns `{1, 0}`). The `MapChannelAndFunctionBlock` tables for other cases (types 0, 1, 2, 3, 4, 5, 6, 8) are **not needed** by the FW1814 properties found so far (**unverified** that no other key reaches them).
* **Q-P4 B.3 open row "0x98 image":** `SetHeadphoneSelector` is reached only from the ABSwitch setters (`SetHeadphoneSource`, `SetHeadphoneSecondSource`, `SubmitHeadphoneSourceChange`); `ABSwitch::SendToDevice` writes nothing. So **no `0x98` write happens at init**; the register keeps the device's own power-on state until the first headphone-source property write.
* **Q-P4 B.3 open row "pan half-word order":** the 16-bit pan words are kept in host order and sent as raw memory, so the wire bytes of register quadlet `0x40+4k` are `[lo(ch 2k+1), hi(ch 2k+1), lo(ch 2k+2), hi(ch 2k+2)]` with `lo = (−p>>1)&0xff`, `hi = (p&1)<<7`. Whether that matches the device's expectation is the reference's behaviour; **verify against a capture / FFADO special_mixer pan decode at the integrated run**.
* **Sleep/wake (not ported):** `SystemWillSleep @0x22b16` (`SetBlankSlateClockSource`, pause, external-sync off, `DisconnectAllPlugs`) and `SystemWokeUp @0x22d76` (`IOSleep(500)`, resend, blank slate, `ConnectAllPlugs`, resume) are device virtuals `0xb88/0xb90`; the caller is `performPowerStateChange @0x1e96` (IOAudioDevice power hook).
