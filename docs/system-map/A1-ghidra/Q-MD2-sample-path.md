## 1. Observations (cited)

1. **IOAudioFamily entry points are on `FWDiscreteEngine`** (vtable `0xac8` clipOutputSamples @0x188c6, `0xad8` convertInputSamples @0x18aa6): `clipOutputSamples` ignores its `mixBuf`/`sampleBuf` arguments and calls `ClipSubEngineOutput(this, 1, first, num, fmt, stream)` @0x18884. That ORs the mask into `[+0x12c]`; when `(mask & [+0x128]) == [+0x128]` (every active sub-engine asked) it clears `[+0x12c]` and calls `vt[0xc38]` = `FWBaseEngine::MainEngineClipOutputSamples`. `convertInputSamples` fetches `vt[0xc10]` (`GetMultichannelInputBuffer` @0x1178a = `[+0x1a8]`), calls `ConvertSubEngineInput` @0x188e4 (if `[+0x130]==0` → `vt[0xc40]` = `ConvertInputSamplesCore`; mask handling like the clip side) and `memcpy(destBuf, [+0x1a8], fmt.fNumChannels*num*4)`. `destBuf` is filled from index 0 (consistent with memory `reference_convert_input_samples`).
2. **`MainEngineClipOutputSamples` @0x3ed4**: `mix = outStream->vt[0xa00]` (= `IOAudioStream::getMixBuffer`, from the FWStream vtable dump); requires `[+0x2ec] == outStream.fNumChannels` and `[+0x2f0] == inStream.fNumChannels` (stream offsets `0xb0` = the format struct, `0xc0` = `fIsMixable`, checked against `IOAudioTypes.h` of the 10.13 SDK); if mixable, `mix += fNumChannels*first*4`; then `vt[0xc90]` = `ClipOutputSamplesWithMixPtrAdjusted(mix, [+0x208], first, num, fmt, stream)`. `[+0x208]` is the output sample ring data (`ResetSampleBuffers` @0x57f8: `[+0x208] = [+0x1e8]`), used as the int scratch.
3. **`ClipOutputSamplesWithMixPtrAdjusted` @0x40aa**: if output stream sample format == `0x63616333` ('cac3'): `if ([+0x2d4] && num < 0x601) vt[0xca8]` (`ClipAC3Output` @0x11c44) else `vt[0xca0]` = `FWEngine2::ClipPCMOutput`.
4. **`FWEngine2::ClipPCMOutput` @0x11d72**: `_Float32ToNativeInt32_X86(mix, scratch, outStreamCh*num)`; if peak proc `[+0x308]` set → zero a region of the device peak buffer and call it (never set for the FW1814: only `FWAudiophileDevice::SetupAudioEngine` writes `[+0x308]`); then a loop over TX packets: `FWDCLOutputProgram::GetPacketFrameContainingSampleIndex(done+first, [+0x224] SYT, &framesLeft, &pkt, &frame)` @0x26100 (14-byte forward to `TPacketPool` @0xa7aa); count `n = framesLeft`, and `n = framesLeft + done - num` when `framesLeft + done > num` (asm 0x11e2d..0x11e3e — literal, see §3); if `[+0x328]==0` call `[+0x300](scratch + outStreamCh*done, dstFrame, n)` (else `RemapSampleFramesForOutput`); `done += n`.
5. **`_Float32ToNativeInt32_X86` @0x2d13d**: `v = x * 8388608.0f + 0.5f` (constants at `0x2ff00/0x2ff10`), clamp to `[-2147483648.0, 2147483520.0]` (`0x2ff20/0x2ff30`), `cvtps2dq` with **MXCSR rounding set to "down"** (`stmxcsr; and $0xffff9fff; add $0x2000; ldmxcsr` at 0x2d14e..0x2d16a) = `floor(v)`. The <4-element scalar tail truncates a double instead (decomp, `0x2ffe8..0x2fff8`). `_NativeInt32ToFloat32_X86` @0x2c8e0 multiplies by `1.1920929e-07` = 2^-23 (`0x2fe80`).
6. **`_RearrangeSampleFrameLRLR{4,6SkipMIDI,8…14SkipMIDI}`** (and the non-SkipMIDI 6…14 which have destination stride N): per frame N samples are clamped to ±24 bit (`0x7fffff` / `0xff800000`) and stored as `u*0x1000000 + (u&0xff00)*0x100 + (u>>8 & 0xff00) + 0x40` = AM824 MBLA quadlet in wire byte order (`40 b2 b1 b0`); source stride N, **destination stride N+1** for the SkipMIDI forms (the frame's MIDI quadlet is not written). Channel order is the identity for every size (verified by script over all 11 decompiles).
7. **Input side.** `ConvertInputSamplesCore` @0x496a (`vt[0xc40]`): needs `num != 0`, `[+0x2d4]==0` (not AC3), the two stream-channel checks of item 2; `IOSynchronizeDCLPrograms`; then if `num+first < 0x2001`: `written = ring.writeOff([+0x280]) / ((m+inCh)*4)`, `last = first-1+num`, `d = written-last` with a ±0x2000 wrap correction (if `|d| < 0x801` no wrap); `d < 0` → `if ([+0x251]==0) [+0x250]=1` (resync request, no consumer found) and nothing converted; else `IOSynchronizeDCLPrograms`, `vt[0xc98]` = `ConvertInputSampleData(num, [+0x290] + (m+inCh)*first*4, [+0x1d8], [+0x1a8])`, `[+0x33c] = num+first`. `ConvertInputSampleData` @0x4624: if `[+0x320]==0` → `[+0x310](inCh*num, src, scratch, [+0x318])` (default LLRR/LRLR procs when `[+0x310]==0`, chosen by `[+0x2d5]`), else `ConvertSampleFramesFromInput` (remap); then `_NativeInt32ToFloat32_X86(scratch, floatDst, inStreamCh*num)`.
8. **`FW1814Device::ResetRearrangementProcs` @0xcad4** (vt `0xaf8`, called from `SetupAudioEngine` @0xed34 and from `SetIOFormat`): output channels `[+0x2e0]` 4→LRLR4, 6→LRLR6SkipMIDI, 8/10/12/14 likewise, otherwise `[+0x300]=0`; input `[+0x2e4]==2` → `_ConvertInputFramesOneStereoPairSkipMIDI` (arg 2; source stride 3 = 2 samples + MIDI), else `WorkaroundFor1814InputDelay` with arg = the device. `SetIOFormat` copies the remap pointers from DeviceChannels `+0x18/+0x20/+0x28`; those are 0 for every FW1814 row (FWRates.h, read from the binary tables in R45).
9. **`WorkaroundFor1814InputDelay` @0xcba4** (`FW1814Device__WorkaroundFor1814InputDelay.c`): device state: `[+0x1b8c]` index table, `[+0x1bcc]` 16×6 raw quadlets, `[+0x1d4c]` counter. The constructor @0xf04a fills the table with `i*6` (`FW1814Device__FW1814Device.c`), so it is a plain 16-frame history. Per frame (source stride `inCh+1`): `slot=((++counter)&15)*6`; old = history[slot][0..5]; history[slot] = in[1,2,3,5,6,7]; out[0]=in[0], out[1]=in[4], out[2..7] = old[0,3,1,4,2,5], out[8..9]=in[8..9], `inCh>10` → out[10..11]=in[10..11], `inCh>12` → out[12..15]=in[12..15]; all unpacked with `((x&0xff00)<<8|x>>24)*256+(x&0xff0000)>>8` = signed 24-bit.

## 2. Implications for the clone (reasoning, not observation)

* `FWSamples.{h,cpp}` re-implement items 5, 6 and the stereo-pair/unpack arithmetic in C (the SSE loops have no other effect); `FWDiscreteEngine` carries item 1, `FWBaseEngine` items 2, 3, 7, `FWEngine2::ClipPCMOutput` item 4, `FW1814Device::{ResetRearrangementProcs,WorkaroundFor1814InputDelay}` items 8–9. Host test (scratchpad, clang): float→int scale/clamp, pack/unpack round-trip over the 24-bit range, rearrange stride and untouched MIDI quadlet all pass. Behaviour on the wire is **not** tested (airliner rule: integrated run).
* `floor()` is used for all lengths; the reference's scalar tail (<4 elements) truncates. Only affects requests under 4 samples, which CoreAudio never issues (num × channels ≥ 64×4).
* Device `[+0x1b8c]` table is not stored — the identity table is folded into `(counter & 15) * 6`.

## 3. Not ported / open (labelled)

* **Not ported (never reached by the FW1814):** `_SamplePeaks*` (peak proc `[+0x308]` null), `_ConvertLLRR*`/default input procs, `_ConvertInputFrames1212CS` (ProjectMix), `ConvertSampleFramesFromInput`/`RemapSampleFramesForOutput` (DeviceChannels remap pointers 0), `_Rearrange*LLRR*`/`WithMIDI`/`16Bit2`/`Reverse` (other products), the `_Float32To{Native,Swap}Int{16,24}`/`_Swap*ToFloat32` converters (CoreAudio client formats; the engine's own streams are fixed 24-in-32 — not on the FW1814 path).
* **Peak meters:** the FW1814 meter data does not come from `_SamplePeaks*` (peak proc null). Where `peak[52]` is filled is M-F, **unverified**.
* **Literal per-packet count** (item 4): `framesLeft + done - num` equals the remaining frame count only for requests aligned to the packet size (CoreAudio's power-of-two buffers are); misaligned requests would over-convert within the packet but never past it. Mirrored as is (**observation**); whether the reference relies on alignment is **unverified**.
* `[+0x250]` (resync request) has no consumer in any decompile → **unverified** meaning; kept as a field.
* `WorkaroundFor1814InputDelay` reason (analog-input group delay of the converter?) is **guess — needs verification**: a loopback capture with the SL driver (B5) would show whether channels 1,2,3,5,6,7 arrive 16 frames later than 0 and 4.
