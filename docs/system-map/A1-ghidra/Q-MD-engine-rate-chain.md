## 1. Observations (cited)

1. **Class chain:** `IOAudioEngine → FWDiscreteEngine → FWBaseEngine → FWEngine2` (the `FWBaseEngine` ctor @0x633a calls `FWDiscreteEngine`'s). `FWPairEngine` uses `[+0x118]` as a pointer to the main engine; `FWDiscreteEngine` uses the same slot as the pair-engine array. `FWBaseEngine::pauseAudioEngine/resumeAudioEngine` call IOAudioEngine's directly (GOT), so `FWDiscreteEngine`'s versions (mask save/restore, `[+0x110]` shared-state int) serve the pair engines only.
2. **IOAudioEngine member offsets** used by the reference match the 10.13 SDK layout exactly (computed with the 10.13 headers: numSampleFrames `0x88`, sampleRate `0x8c`, runEraseHead `0x98`, stopPosition `0x9c`, configurationChangeInProgress `0xa5`, state `0xa8`, status `0xb0`, audioDevice `0xb8`, inputStreams `0xd0`, outputStreams `0xe0`, numActiveUserClients `0x100`). Vtable calls through `PTR_vtable_000300b0 + X` are non-virtual base calls of slot `X - 0x10`.
3. **Streams:** `RecreateAudioStreams @0x4546` creates `[+0x218]` with direction 0 (output) and `[+0x210]` with direction 1 (input) — Q15c's "outputStream@0x210" is reversed. Sample rings (`ResetSampleBuffers @0x57f8`): `(channels + m) · 0x8000` bytes each (8192 frames × 4 B per channel, matching `setNumSampleFramesPerBuffer(0x2000)` in `initHardware`); `[+0x258]` is the 4 KiB SYT table (2048 × u16) and the input sample ring is the shared-sync `inputRing` at `[+0x268]`; `FWDCLSharedSyncData` is embedded at `[+0x240]` with `engine = this` at `[+0x2b8]`.
4. **DeviceChannels** (0x80 B): see `FWRates.h`. Rate list = 44.1, 48, 88.2, 96, 176.4, 192 kHz (zero-terminated at `0x2f890`). `GetDeviceChannelsForSampleRate @0xc998`: input fields/groups 0-1 from the table selected by `mode & 0x08`, output fields/groups 2-3 by `mode & 0x10` (Q13's comment "bit 3 → ADAT output" is wrong; Q-P4 and the decompile agree). `SetupAudioEngine @0xed34` therefore gives outputs 6/12 (bit 4) and inputs 10/16 (bit 3); its first sets are `[+0x2d5] = [+0x2d6] = [+0x348] = 1`, `m = 1`.
5. **Rate chain** (Q15c re-read with vtable names): `performFormatChange @0x3e54` → work-loop `runAction(ActionPerformFormatChange)` → `FWEngine2::PerformFormatChange @0x124cc` (`vt[0xc88]`) → (PCM) device `RequestFormatUpdateForSampleRate @0x2a84` → table index → `FWBaseEngine::SetIOFormat @0x42aa` → cache counts, `setSampleRate` (`vt[0xb58]`), `vt[0xce0]` = `FWEngine2::PerformSampleRateChangeCore @0x117e6` (if connected and not external-sync-locked: `DisconnectAllPlugs`, base `@0x479e`, `[+0x345] |= 0x80`) → `SetStreamFormat` for both streams (lpcm / sint, 24 bit in 32, high-byte aligned, big-endian, mixable; one available format per list rate) → `CompletePendingStateChanges`. Slot names: `vt[0xb00]`/`[0xb08]`/`[0xb10]` = begin/complete/cancelConfigurationChange; `vt[0xce0]` = `PerformSampleRateChangeCore`; `vt[0xaf8]` on the device = `ResetRearrangementProcs`; `vt[0xcb8]/[0xcc0]/[0xcc8]/[0xc78]` = ConnectAllPlugs / DisconnectAllPlugs / RecalculateBandwidth / UpdateDCLProgramsWithNewPacketSizes.
6. **Pending mask** `[+0x344]` (u32; the code ORs the bytes `[+0x345]`, `[+0x346]`, `[+0x347]`): consumer `CompletePendingStateChangesAction @0x3b2c`: `0x1` busy (return); `0x48000` with plugs connected → `DisconnectAllPlugs`, then `|= 0x8000`; `0x800000` RecreateAudioStreams; `0x200000` ResetSampleBuffers; `0x400000` ResetStereoPairIOFormats; `0x40000` UpdateDCLProgramsWithNewPacketSizes; `0x8000` (unless `0x80000` with no external sync and no `[+0x348]`) ConnectAllPlugs; `0x80000` RecalculateBandwidth; `0x1000000` IOSleep(1000); `0x100000` notify `MASampleRate`; then MIDI restart; mask cleared even on failure. Producers: `PerformSampleRateChangeCore |= 0x1d0000`; `SetIOFormat`/`ChangeSampleRateToFDFValue |= 0x6f0000`; `initHardware |= 0x70000 / 0x208000`; `RecreateAudioStreams |= 0x200000`; `UpdateDCLProgramsWithNewPacketSizes |= 0x1000000`.
7. **Latency** (`ResetLatency @0x3f7a`): input latency = `(rt + 1) >> 1`, output latency = `rt >> 1`, sample offset = `GetSafetyOffsetForFDF`; `rt` = FW1814 table 210/210/225/358/378/642/698 (Q10), safety offsets 44/44/48/88/96/176/192 frames (`@0x1d58`, new here).
8. **Start/stop** (with Q-START): `StartIsochStreams @0x54b0` refcounts `[+0x22c]`, on 0→1 clears the SYT/input-ring state and calls `vt[0xcd0]` = `FWEngine2::StartAudio` (PCM → `StartPCMAudio`: RX Start then TX Start; AC3 → `StartAC3Output`). `StopIsochStreams` decrements and calls `vt[0xcd8]` `StopAudio` (TX Stop, RX Stop). `ActivateSubEngine(1)` (called by `performAudioEngineStart`) starts the isoch streams unless the engine state is paused.
9. **Bandwidth** `GetBandwidthBytesAtSampleRate @0x1ee2` uses the engine's CURRENT SYT interval (`[+0x224]`, 0x20/4 when no engine), not the target rate's; `RecalculateBandwidth @0x1235a` sets `MABytesPerCycle`.

## 2. Corrections this item forces
* **Q13:** `FWBaseEngine` derives from `FWDiscreteEngine`; the SetupAudioEngine comments swap in/out (outputs 6/12 by bit 4, inputs 10/16 by bit 3).
* **Q15c:** input stream is `[+0x210]`, output `[+0x218]`; the `[+0xce0]`/`[+0xaf8]` names are the ones in R2 and in §1.5 here.
* **Q10:** safety offsets added (`GetSafetyOffsetForFDF`).

## 3. Clone mapping (builds clean on the build PC, `kextutil -t -n` OK, nothing loaded)
`FWRates.h` — rate list, four DeviceChannels tables, `FWComposeDeviceChannels`, latency/safety/bandwidth functions. `FWDiscreteEngine` — `ActivateSubEngine/DeactivateSubEngine/stopAudioEngine/performFlush/stopEngineAtPosition`. `FWBaseEngine` — `init/initHardware/stop`, `performAudioEngineStart/Stop`, `getCurrentSampleFrame`, `performFormatChange` (work-loop gate), `PerformSampleRateChangeCore`, `SetIOFormat`, `SetStreamFormat`, `ChangeSampleRateToFDFValue`, `ResetLatency`, pending-state machine, `Add/RemoveDCLProgram`, `StartIsochStreams/StopIsochStreams`, base `StartAudio/StopAudio`, `RecreateAudioStreams`, `ResetSampleBuffers`, `performErase`, `SetExternalSyncEnabled`. `FWEngine2` — `initHardware` (TX/RX programs on the shared sync, primary flags, connection manager), `PerformFormatChange` (AC3 fork), `UpdateDCLProgramsWithNewPacketSizes`, `RecalculateBandwidth`, `ConnectAllPlugs/DisconnectAllPlugs/ConnectAudioMIDIChannels`, `StartAudio/StopAudio`, `StartPCMAudio`, `Activate/DeactivatePCM*`. ## 4. Open / not ported (explicit)
* **Sample path (M-D2):** `clipOutputSamples` / `convertInputSamples` are empty; the `_Convert*`, `_Rearrange*`, `_SamplePeaks*`, `Float32↔Int*` free functions (≈40, several SIMD) and `ResetRearrangementProcs` (per-channel-count proc selection decoded in `FW1814Device__ResetRearrangementProcs.c`, `WorkaroundFor1814InputDelay` for non-stereo input) are not ported — the engine cannot yet carry audio, only AM824 silence.
* `FWStream::setFormat @0x10bda` / `validateFormat @0x11090` / `mixOutputSamples @0x10b38`: the reference carries private copies of IOAudioFamily's bodies built against the 10.7 headers (`IOAudioStreamFormatDesc` is 0x48 bytes there, opaque on 10.13). The clone uses the stock implementations; **what the reference changes is unidentified.**
* MIDI (M-H: `SetMIDIInputPorts/OutputPorts`, `StartMIDI/StopMIDI`), AC3 (M-I: `Enable/DisableAC3Format`, `AddAC3Format`, `StartAC3Output`, `Activate/DeactivateAC3Output`), pair engines and `ResetStereoPairIOFormats` (M-J), user-client / `SetStaticPropertyAndNotifyUserClients` (M-F: logs only), peak-meter clearing in `performAudioEngineStop` (M-F), `SetChannelNamesForMainEngine`, `NameAndActivatePairEngines`, HSCI restart in `StopIsochStreams` (M-E), external-sync detection (`DetectExternalSyncChanges`).
* `[+0x2d1]` (`fExtSyncLocked`) meaning unverified; `ConnectAllPlugs` wrapper `FWStreamControl::ConnectAllPlugs` is unused by the engine (the engine holds the gating itself, as in the reference).
* Whether IOAudioFamily on 10.13.6 accepts the reference's `performFormatChange` pattern (work-loop `runAction` from inside a client call) and the stream-format replication is unverified until the integrated run.
