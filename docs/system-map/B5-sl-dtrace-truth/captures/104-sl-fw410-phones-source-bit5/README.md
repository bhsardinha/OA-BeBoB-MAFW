# Capture 104 — FW410 phones source bit 5 (`MAHeadphoneSourceV2 & 0x20`), SL rig v1.9, 2026-10-26 — INCONCLUSIVE

Question (PN410 §5 item 1): which bus is the sixth phones source the v1.11.2 kext accepts (`SetHeadphoneSource` bit 5 → register word bit 26)?
Method: a −40 dBFS 1 kHz tone (`afplay`, 96 kHz, SW return 1/2 → out 1/2 only); `MAHeadphoneSourceV2` written with `slprops.py set` (same 32-bit scalar form as the panel's writes, capture 103), hardware peak quadlets read from the status packet `0xFFC7:0x00600000` (`slfwread quad`): q4/q5 = out 1/2, q14-q17 = two further output pairs (**assumed** phones = q14/q15, aux = q16/q17; not verified). Script `sl-fw410-phones-src.sh`, raw `peaks.txt`.
Result: not consistent between passes. From the restored state q14/q15 carried the tone with mask 1; after a write of 0, writes of 1 / 33 did not bring it back; a full restore did; in a later pass (restore before each mask) q14/q15 stayed silent for every mask without aux, and with the aux sends of SW return 1/2 at 0 dB q14-q17 carried the tone for every mask including 0. So in **v1.9** the phones-source write does not act on its own (it depends on other writes), and v1.9 is not the spec (v1.11.2 `SetHeadphoneSource` writes register 0x68 itself).
Decision: the clone implements bit 5 as v1.11.2 does; the bus is identified by ear on the first run with our driver (F7). Rig restored (`slprops.py restore` + settings file).
