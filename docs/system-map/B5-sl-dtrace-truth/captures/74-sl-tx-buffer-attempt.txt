# Capture 74 — SL Mac Pro, driver v1.9, device idle, 2026-10-14: attempt to read the live TX packet content (for A1-Q17.2). PARTIAL.
## What was observed
* Method: fbt::IOBufferMemoryDescriptor::getBytesNoCopy return values (kernel_task) + dtrace tracemem() of kernel buffers (read-only). Kernel is the 32-bit i386 build, so the kext loads as a relocatable object (kextstat base 0x160e000) and kext return addresses cannot be mapped to the on-disk i386 slice offsets.
* `976c1000` (8 KiB class buffer) is an **OHCI descriptor program** (TX): first bytes `01 0d 00 00 90 ff ff ff` = CIP header template (SID 1, DBS 0x0d = 13 quadlets/block, DBC 0; second quadlet FMT 0x10, FDF/SYT 0xff…), then OUTPUT_MORE_IMMEDIATE/OUTPUT_LAST descriptors: `a8 01 0c 10 <phys 0x77f6xxxx>` = reqCount 0x01a8 = **424 bytes per packet = 8 (CIP) + 8 events × 13 quadlets × 4**, status/branch words `0x77f93003…`; most descriptors carry control word `0x100c`, a repeating subset carries `0x183c` (extra interrupt/wait bits) — consistent with Q-OHCI-interrupt (only DCLs with a callback get interrupt bits). Matches the engine's idle configuration (12 audio out + 1 MIDI = DBS 13 at MAClockSource 0x40000014).
* Other `97b05000…97b3f000` buffers are 21 further OHCI descriptor programs (same `27 80 61 …` OUTPUT/INPUT descriptor pattern); `e1b000`, `e39000-e3b000` (DBS 0x11 = 17) and `e3c000` (DBS 0x0b = 11) hold CIP headers of other (RX-side) programs. Buffers `974a2000, 97333000, 97b82000, 9741a000, 97def000` read as all zero (first 4 KiB).
* The audio **data** buffers are referenced only by physical address (0x77f6xxxx); the SL has no /dev/mem and the 32-bit kernel has no physical map, so their content (labels 0x40 / 0x80 / 0xCF) could not be read.
* `inTaskWithPhysicalMask` never fired during a 7-minute window that included the user's interface power cycle (no new pool allocation: the kext instance and its pools persist across a power cycle; the BYTES calls around +9.9 s and +40.5 s are OHCI/IOKit reuse of existing descriptors).
## Not achieved
Reading the label bytes of the live TX data blocks. Would require catching the pool allocation at kext load (unload/reload of the official kext on the only reference rig — not done) or a physical-memory reader.
