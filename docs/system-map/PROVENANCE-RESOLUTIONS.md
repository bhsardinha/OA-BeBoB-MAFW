## R1. Stream-kick order and timing (audit #1)

`FWEngine2::ConnectAudioMIDIChannels @ 0x12156` (`mafw.asm:20779`). `[+0x348]` is set to 1 by `FW1814Device::SetupAudioEngine @0xed73` (Q3a §3 Correction), so the `!= 0` branch is the FW1814 path:

| Step | Asm | Meaning |
|---|---|---|
| 1 | `0x121c9 callq *0x120(%rax)` on `[+0x350]` | start TX DCL program |
| 2 | `0x121d7 IOSleep(0x1f4)` | 500 ms |
| 3 | `0x12211 movl $1,%esi` → `0x12246 callq *0xb50(%r10)` | `AVCControlPlugSignalFormat(INPUT)` = `00 FF 19 00 90 <SFC> FF FF` |
| 4 | `0x1224d IOSleep(0x1f4)` | 500 ms |
| 5 | `0x12263 callq *0x120(%rax)` on `[+0x358]` | start RX DCL program |
| 6 | `0x122ae xorl %esi,%esi` → `0x122bb callq *0xb50(%r14)` | `AVCControlPlugSignalFormat(OUTPUT)` = `00 FF 18 00 90 <SFC> FF FF`, no sleep after |

## R4. ReconnectP2P / BusReset (audit #9)

* `ReconnectP2P @0xe1ea`: `e->vt[0xcc0]` (DisconnectAllPlugs) → `e->vt[0xcb8]` (**ConnectAllPlugs**, not Quiesce) → `IOSleep(0x44c)`=1100 ms → `cmpb $0,0x2d0(engine); je 0xe23c` (**calls the tail when `[+0x2d0]==0`**, inverted in Q4) → tail-jump `this->vt[0xb60](this, [+0x144]=fMode, 1)` = `SetClockSourceInternal(fMode, blankSlate=true)`.
* `[+0x2d0]` is **not** "fRunning". The only writer is the function at `0x53f0` (between `ChangeSampleRateToFDFValue`'s jump table and `TellClientsSampleRateChanged`): `if ([+0x2d0] != arg) { if ([+0x22c]==0) [+0x2d0]=arg; else IOLog("Cannot change sync mode while audio/MIDI streams are running"); return 0xE00002E6 }` (`0x53f0..0x541b`). `FWEngine2::SetExternalSyncEnabled @0x11bc0` copies `[+0x2d0]` into the TX DCL program `[+0x350]+0x618`. So `[+0x2d0]` = **external-sync (slave-to-external-clock) mode flag**; init = 0 (`FWBaseEngine::init 0x5dfc`). Consequence: the ReconnectP2P tail re-sends the clock source only when the engine is **not** in external-sync mode. Field name `fExternalSync` is our label (inferred from the log string + `SetExternalSyncEnabled`) — **hypothesis**, check = decode a caller of `0x53f0`.
* `BusReset @0xe53a`: builds a `CallCenter` whose inner callable stores `0xBF1` at `0xe5ab`; Itanium PMF with odd low bit ⇒ virtual, vtable offset `0xBF1-1 = 0xBF0` ⇒ `ReconnectP2P`. It then tail-calls `UKernelCallHelpers::InvokeOnNewThread` (`0xe5cc`). So **BusReset == "run ReconnectP2P on a new thread"**, not a separate path. `vt[0x688]` is `getWorkLoop`.

## R8. Part A completion batch 1 (2026-10-14)

* **Pool pages (A1-Q-DCL.2).** `TPacketPool::Initialize @0xa3e6`: `[+0x28] = floor(0x1000 / packetSize[+0x20])`, `[+0x34] = 0x1000 - [+0x28]*packetSize`, `[+0x24] pages = floor([+0x18] / [+0x28]) + 2` (`0xa45c..0xa467`), buffer = `inTaskWithPhysicalMask(kernel_task, pages<<12, bus->vt[0x140]() & ~0xFFF)` with options 0 (`0xa46d..0xa49e`). The meaning of `[+0x18]` (third argument) is **unverified** (it is also stored `>>2` in `[+0x1c]`); growth in practice **unmeasured**.
* **`vt[0x850]` (A1-Q-CMP.3).** `IOFireWireNub` vtable `0x36a50` (+0x10+0x850 = `0x372b0`) = `IOFireWireNub::FWSpeed() const @0xef38` in `IOFireWireFamily` 4.7.2 (10.13.6, `_refs/macos-10.13.6-fw/IOFireWireFamily.bin`); `IOFireWireDevice` vtable `0x35ac0` gives the same entry. The 122-quadlet payload meaning (IEC 61883-1 oPCR payload field) is **unverified** here (spec not in repo).
* **`[+0xa5]` (A1-Q12.1, AUD-C4-02).** `IOAudioEngine::beginConfigurationChange` (IOAudioFamily 10.13.6, `_refs/macos-10.13.6-fw/IOAudioFamily.bin`, `0xa3d8`) does `movb $1, 0xa5(%rbx)`; `completeConfigurationChange` tests then clears `0xa5(%r14)`. So `[+0xa5]` = `IOAudioEngine::configurationChangeInProgress`, **not** an AC3 flag. AC3 stays `[+0x2d4]`. `SetIOFormat @0x42c4` therefore calls `beginConfigurationChange` only when none is in progress.
* **`SwitchDigitalSignals @0xe5dc` (A1-Q5.6, C2).** Not an AV/C command: fetches the device's `DeviceChannels` (`vt[0xa60]`), engine `vt[0xc48]`, `FetchIndexIntoSampleRateArray([+0x220])`, calls `FWBaseEngine::SetIOFormat(channels, idx)`, then selects the meter template by the engine's **output** channel count `[+0x2e0]` (6 -> `Sample1814PeaksSPDIF6`, 8 -> `…ADAT8`, 12 -> `…ADAT12`, else `…4All`) stored at engine `[+0x308]` (*corrected later the same day, R12: an earlier draft said 'input'; the INPUT format call uses `[+0x2e4]`, the OUTPUT call `[+0x2e0]`*) (`0xe63d..0xe67b`).
* **`SetBlankSlateClockSource @0xe4f0`.** Calls `vt[0xb60](fMode & 0x1c) + 0x40000003, blankSlate=1)` then `IOSleep(0x9c4)`; `0x1c` keeps bits 2-4 and drops bit 5 (S/MUX) and bits 1:0. The *purpose* of the 2500 ms / 300 ms sleeps (PLL settle) remains **unverified**.
* **SL live (capture `B5-sl-dtrace-truth/captures/71-*.txt`, driver v1.9).** (a) Relaunching the Panel with saved prefs produced **no** `is_io_registry_entry_set_properties`; (b) restarting the helper daemon produced **three** property writes from the helper (60, 6570, 6570 bytes) within 18 ms — the helper reapplies the saved settings (A1-Q3b.3: who = helper, **payload content not decoded**: >4 KiB out-of-line, only the byte counts were seen); (c) no kext `IOSleep(500)` seen on playback start (inconclusive, see capture).

## R12. Channel counts per digital mode (A1-Q3.2) — 2026-10-14

`FW1814Device::SetupAudioEngine @0xed34`: `testb $0x10, fMode[+0x144]` -> clear: `[+0x2ec]=[+0x2e0]=6`, set: `12` (0xed84-0xedae); `testb $0x8, fMode` -> clear: `[+0x2f0]=[+0x2e4]=10`, set: `16` (0xedb8-0xede2). `ConnectAudioMIDIChannels` uses `[+0x2e4]` for the INPUT format (esi=1, 0x12207) and `[+0x2e0]` for the OUTPUT format (esi=0, 0x1229d). So **outputs = 6 / 12 (bit 4, optical-OUT ADAT), inputs = 10 / 16 (bit 3, optical-IN ADAT)**. Q3's 'in 6/12 by bit 4, out 10/16 by bit 3' is swapped. Live SL v1.9 (captures `67a/67b`, `IOAudioStreamDirection` 0 = output, 1 = input): at 48 kHz output stream 12 ch / input stream 16 ch; at 96 kHz output 8 / input 12 - equal to kext tables `sADAT44_48 {16,16,12,12}` (in 16, out 12) and `sADAT88_96 {12,12,8,8}` (in 12, out 8) read as (in, in, out, out); S/PDIF base = in 10 / out 6. Hardware arithmetic: in = 8 analog + (2 S/PDIF | 8 ADAT) = 10 | 16; out = 4 analog + (2 | 8) = 6 | 12. The `67a` file name says 'spdif-mode' but its counts (16/12) are ADAT-at-48k counts - its label is **unverified/suspect**.

## R24. Where the "1.11.3" comes from + installer provenance (2026-10-14)

Primary evidence, from the DMG itself (`_vendor/M-Audio_FireWire_1-11.2.dmg`, sha256 `37f3c86f…aaf7`): the installer `M-Audio FireWire Installer.pkg` has a `Distribution` script titled "M-Audio FireWire 1.11.2" (`version 1.11.2.22267`, product version 1.11.2) and its `<bundle-version>` manifest lists **`com.m-audio.driver.firewire` = 1.11.3** at `Library/Extensions/M-AudioFireWireBeBoB.kext`, next to the MIDI plug-in 1.11.2, panel 1.5.2, prefpane 1.3.4, status app 1.2.2. So "1.11.3" is the kext's own `CFBundleVersion` inside the 1.11.2 installer; there is no separate 1.11.3 download implied. Signatures (`pkgutil --check-signature`, `codesign -dvvv`): the `.pkg` is signed by **Developer ID Installer: inMusic Brands, Inc. (QGX2722FLV)**, trusted timestamp 2014-05-02 23:48:21 UTC; the `/Library/Extensions` kext (x86_64-only, 659,632 B, sha256 `5532c6e8…ceb17`) is signed **Developer ID Application: inMusic Brands, Inc.**, timestamp 2014-05-02 20:47:39; the uninstaller app is signed by the same identity (20:48:15). ## R74. Reported: audio freeze and ~200 ms loop when a file is deleted during playback - 2026-10-17

## R107. AP-3.9: async AV/C teardown safety and diagnostics for the new paths - 2026-10-20
The async AV/C queue (ref `AVCCommand @0x17fc` / `FinishAsyncCommand @0x16c8`) keeps a raw unit pointer in each command; the Rev2 mixer sends everything through it, so a completion after the unit is freed would panic. Clone safety (labelled deviation in `FWAvc.h`): each queued command holds a reference on the unit (released in `FinishAsyncCommand`, on a refused submit, or when dropped); `stop()` → `DrainAsyncQueue()` refuses new commands, releases the never-submitted ones and `cancel()`s the in-flight head (`IOFireWireAVCAsynchronousCommand::cancel`, 10.13 SDK `IOFireWireAVCUnit.h:70`), which is released only by its own completion — a missing completion leaks (kextunload refused) instead of panicking. Diagnostics: `DebugTrace` (MADebugTrace ring) is now locked (callers on the engine, work-loop and HSCI threads) and the Rev2 paths log the 0x2F walk (entries, result) and the 0x1A sync (source, result).
