# H13 — clone implementation of H.3 (gating) and H.4 (settings persistence) (2026-10-15)

No new decompilation: this records how `openaudio-fw1814/firmware-helper/{Gating.c,Settings.c,main.c}` realise H2 (guards), H7 (lifecycle), H8/H11 (persistence) and the kext side of Q-MF. Every behaviour below cites its source; the C code mirrors the reference's Objective-C structure.

* **Gating (H2 `deviceMatched:` guards, A3-M9 §2):** firmware start (`MAFirmwareStart`) and settings replay run only when the system is not sleeping (`IORegisterForSystemPower`; `kIOMessageCanSystemSleep` never vetoed, `…WillSystemSleep` sets the flag, `…SystemHasPoweredOn` clears it and re-walks) and a console user is logged in (`SCDynamicStoreCopyConsoleUser`; `loginwindow` = nobody; changes observed through `State:/Users/ConsoleUser`). On wake and on login the existing nubs/devices are re-walked (H7: the daemon outlives the login window). **Behaviour change vs the M-FW build:** the M-FW helper wrote `MAFirmwareStart` immediately; the gated helper defers it until a user is logged in, exactly as the reference does. `--no-gate` restores the immediate behaviour for bench runs.
* **Settings (H11):** per attached `com_openaudio_FW1814Device` the helper opens its own user client (type 0), registers a Mach port with `IOConnectSetNotificationPort(conn, 0, …)` (the kext's type-0 dirty-property port, Q-MF), reads the XML body at message offset `0x24` (24-byte user header + type, refCon, generation; discriminator `0` at offset `0x18`), `IOCFUnserialize`s it, merges it into the device's settings dictionary (only while the gate is open) and (re)arms a 4 s one-shot timer. The commit writes the dictionary with `CFPreferencesSetValue(key = GUID as upper-case hex without `0x`, appID `com.m-audio.device-settings.firewire`, user = console user, AnyHost)` under the console user's effective uid/gid (the reference's `WithCurrentEffectiveUserAndGroup`). At attach and at login: saved dictionary → one `IORegistryEntrySetCFProperties`; nothing saved → `MAMetaAllProperties` seeds the dictionary, no write. `MAMetaConfigureDCLLatency` is not implemented (dead code, H11).
* **Differences / open:** the reference creates two device instances per start (unexplained, R16) — the clone one. The notification body is copied and NUL-terminated by the helper (the kext sends the serialised text without terminator). `setegid/seteuid` around the preference write is the clone's choice of "drop to the user" (the reference's helper does the same through a Carbon-era call) — **unverified** on 10.13.6 with the daemon's `cfprefsd` path; the integrated run checks that the plist lands in the user's `~/Library/Preferences`. Not tested against hardware.
