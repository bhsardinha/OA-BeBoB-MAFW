# A4 helper — static audit against the binaries (2026-10-14)

Scope: H1, H2, H4, H5, H7, H8 (matrix items `A4-H1.1 … A4-H8.1`). Bundle: **v1.11.2** `_extracted/helper/M-Audio FireWire Device Helper` (i386, built from `FireWireBeBoB_01.11.002/Source/DeviceHelper`, path string in the binary) and `FirmwareStatusWindow.app`. Tools: `otool -tvV -arch i386`, `strings`, `otool -l` + CFString struct walk (`__DATA,__cfstring`), the existing Ghidra decompiles in `ghidra-exports/decomp/`, the real `_extracted/firmware/fw1814.bcd`, kext `mafw.asm`, and SL v1.9 capture 71. Asm excerpts used here are from `otool -tvV -arch i386` (not archived as a separate file; reproduce with that command).

## H1 — entry + argv dispatch: **verified**
* `_main` (0x21ee): after `getServer:`/`runServer:`, `cmpl $2,%esi; jl` and `testl %edi,%edi; je` guard the argv branch (0x22fe-0x2305): requires argc ≥ 2 **and** a non-nil server. Then `NSLog("Server running")` (0x2311), `strcmp(argv[1], "start")` (cstring 0x68ae) → `NSLog` + selector, else `strcmp(argv[1], "stop")` (0x68c4) → `NSLog` + selector; anything else falls through (0x233f `jne 0x2371`). Matches H1.
* DO server name `MAudioFireWireHelper` is a real cstring (`strings`); matches H5b.
* The launchd plist (`_extracted/helper/com.m-audio.firewire.helper.plist`) has only `Label`, `RunAtLoad=true`, `ProgramArguments=[".../M-Audio FireWire Device Helper","start"]` — same as installed on the SL rig (`launchctl list` shows `com.m-audio.firewire.helper`).

## H2 — bootloader detection: **verified with two corrections**
* The 8 per-product class names are now **read, not inferred**: `com_m_audio_FW410Device`, `…FWAudiophileDevice`, `…FW1814Device`, `…FWSoloDevice`, `…FWOzonicDevice`, `…FWNRV10Device`, `…FWProjectMixDevice`, `…FWLightbridgeDevice` (`strings` on the helper; the loop of 8 in `init` is from the Ghidra decompile). The H2 'unverified' tag on this list is resolved.
* `deviceMatched:` tests `cmpl $0, 0xc(%eax)` (0x3441) on the `MAFirmwareInfo` bytes: non-zero ⇒ upload branch, zero ⇒ halt branch. Kext side: `FWMetaNub::FirmwareCacheInfoRegisters @0x1cc9e` reads **0x50 bytes** from `0xFFFF:C8020000` (device CSR) into `[this+0x90]`, sets `fBootloaderActive [+0xf0] = ([+0x9c] != 0)` (0x1cd09-0x1cd11) and publishes the 80-byte blob as `MAFirmwareInfo` (0x1cd31). So `info[0xc] != 0` ⇔ **bootloader active (ready for upload)** and the blob is **80 bytes**, not '≥ 0x30'. Consistent with the earlier FirmwareHalt finding (R5).
* Correction: the status-UI command is `sudo -u %@ "%@" launch "%@" "%@" "%llX" &` and the helper also has `sudo -u %@ "%@" quit &` (strings); the second `%@` is `statusAppPath` (decomp `updateViewForDevice` @0x2f6a), i.e. the status app's own binary (`…/FirmwareStatusWindow.app/Contents/MacOS/FirmwareStatusWindow`). `launch` is therefore the UI binary's own subcommand (the UI binary has `launch`, `quit`, `progress`, `indeterminate` cfstrings at 0x7130/7140/7150), **not** Nicholas Riley's `launch(1)` — H5's hypothesis is refuted. Log strings use ' -- ' (e.g. 'Firmware is running -- shutting down the firmware', 'Corrupt firmware file -- not updating'), not commas.

## H4 — firmware selection: **verified with corrections**
* Folder literals (CFStrings at 0x96bc/0x96cc/0x96dc/0x96ec, referenced at 0x5b14/0x5b21/0x5b36/0x5b49): `name == "FW"` → folder **"FW 410"**; `name == "FWSolo"` → folder **"FW Solo"**; else the stripped name. H4's pseudocode (`"FW "`→`"FW410"`, `"FWSolo"`→`"FWSolo"`) had the wrong literals (they matched Ghidra's space-less labels). The shipped folders confirm: `Firmware/FW 410`, `Firmware/FW Solo`, `FW 1814`, `FW Audiophile`, `NRV-10`, `Ozonic`, `ProFire Lightbridge`, `ProjectMix`. The product names that trigger the aliases on real hardware remain **unverified** (no FW410/Solo device here).
* `.bcd` header, read from the real `fw1814.bcd` (941,944 B): magic `bCoD`, version 1 (`[0x04]`); `[0x08..0x13]` = ASCII `"20070713"` + `"080440"` (so the four 'date ulongs' the helper reads are ASCII fields: `0x08`='2007', `0x0c`='0713', `0x10`='0804', `0x14`='40  '; H4's hypothesis #4 is **confirmed**); `[0x30]=0x70` CRC start; `[0x38]=936,604` CRC length; `[0x3c]=0xB84C5237` = `crc32(file[0x70:0x70+936604])` (**checked with zlib, match**); `[0x50]=0xE4B0C`, `[0x58]=5228` appendix with `[0x50]+[0x58] == file size` (as A5 found); `[0x60..0x6f]`='Midiman FW 106'.
* `validateFirmwareUpdate:` (0x5cce): rejects length < 0x60 (0x5d98), then requires `actual length ≥ 0x60 + [0x38] + [0x58]` (`leal 0x60(%edx,%ecx); cmpl; jae`, 0x5de6-0x5dec) — a **minimum-length** check (941,928), which the real file (941,944) passes with 16 bytes to spare (the 16-byte product string at 0x60). It is **not** an equality test as H4 implied. Then CRC compare, then `year > 2002` (`cmpl $0x7d2`, 0x5e92) else 'Corrupt: Year %d ?'.
* A5 typo: CRC length `0xE4A9C` = **936,604**, not 937,116 (A5:59).

## H5 — status UI IPC: **verified**
* UI CFStrings at the H5b/H5c addresses: server name `MAudioFireWireFirmwareStatus` (0x7170); icon extensions `png`,`tif`,`tiff`,`jpg` (0x70b0/c0/d0/e0); icon dir `/Library/Application Support/M-Audio/DeviceIcons/` (0x70a0); subcommands `launch`/`quit`/`progress` (0x7130-0x7150). The helper-side server name `MAudioFireWireHelper` is a cstring in the helper.

## H7 — launchd lifecycle: **verified**
* plist keys as in H1 (no `KeepAlive`, `UserName`, `MachServices`, paths). The helper imports no `signal`/`sigaction`/`atexit` (`nm -u` shows only `_exit`, `_objc_exception_try_exit`) — H7's 'no signal handler' is confirmed by the import table.
* SL v1.9 live: `launchctl list` shows the helper resident; `launchctl unload/load` restarts it (new pid) and immediately issues **three** `is_io_registry_entry_set_properties` (60, 6570, 6570 bytes) — see capture 71 and H8.

## H8 — runtime handoff: **verified with one correction**
* `systemWokeUp`'s 1-second settle: `movl $0x3ff00000` (IEEE-754 high word of 1.0) at 0x370a; `sSystemSleeping`; `userDidLogIn:` → `loadPrefsForUser:` per H8, and the SL capture shows the same preference push occurs when the helper (re)starts with the device already attached — consistent with `driverInstanceMatched:` → `MAFireWireDeviceInstance` → `loadPrefsForUser:`/`commitSettings:` (helper strings: `com.m-audio.device-settings.firewire`, `commitSettings:`, `MAMetaAllProperties`, `MAMetaConfigureDCLLatency`). Payload content (6570 B) **still undecoded**.
* Correction: H8's bootloader walkthrough steps 1-2 ('0x10070 … `firmware_running = 0` → Halt') are inverted. `info[0xc] != 0` is the **bootloader** state (upload branch); `info[0xc] == 0` is **runtime** (Halt branch) — see H2 and the kext read above.
