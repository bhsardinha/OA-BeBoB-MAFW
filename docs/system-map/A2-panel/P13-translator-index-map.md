# A2-P13 — Panel translator: channel numbering, rotary mask, ranges, headphone cookies (closes PN.2 open items 1–5)

**Date:** 2026-10-16. **Bundle:** `_extracted/panel/` (panel v1.5.2, project `ghidra-project/panel-app`), Ghidra 12.1.4 headless. **Decompiles:** `ghidra-exports/decomp/pn2__*.c` (59 files, 52 distinct functions: `CXDevice::Choose*`, `Set/GetHW[Indexed]Setting`, `GetHWSettingRange`, `ReceiveRotaryControlAssignments`, `CX1814Device::*`, `CXSelectorHPDevice::*`, `CFW1814DeviceSettings::Map*`, ctor and range data, peak consumers). Scripts: `scripts/PN2VtDump.java` (output `ghidra-exports/pn2-cx1814-vtable.txt`), `scripts/PN2MemDump.java`. **Version skew:** v1.5.2 panel vs v1.9 screenshots (P12); the translator is device-agnostic and consistent with the v1.11.2 kext rows in Q-MAMAP, so it is used as authoritative for index conventions.

## 1. Channel counts and numbering (all indexes are 1-based; 0 = invalid)
`CX1814Device` vtable (`pn2-cx1814-vtable.txt`): `[+0x18]` outputs = **20** (0x14), `[+0x1c]` mixer channels = **32** (0x20), `[+0x5c]` inputs = **18** (0x12), `[+0x60]` headphone channels = **4**, `[+0x64]` direct-monitor channels = 4, `[+0x68]` aux-monitor-switch channels = outputs = 20 (`CXDevice::GetNumberOfAuxMonitorSwitchChannels @0x72166`), `[+0x6c]` SW-return peaks embedded = 0.

| Panel index space | Index → key and element | Source |
|---|---|---|
| Mixer channel id 1..32 | 1..18 → `MAInput<suffix>[id]`; 19..32 → `MASWReturn<suffix>[id−18]` (14 SW-return channels; the FW1814 uses 1..4) | `ChooseMixerBusAndChannelIndex @0x6de56` |
| Mixer pair 1..16 | 1..9 → `MAInput`, 10..16 → `MASWReturn` pair `p−9`; pair p = channels 2p−1, 2p (identity map) | `ChooseMixerBusAndChannelPair @0x6ddbe`; `CFW1814DeviceSettings::MapMixerChannelPairToChannelIDs @0x5c47c` |
| Output channel id 1..20 | 1..14 → `MAOutput[id]`; 15..18 → `MAHeadphone[id−14]`; 19..20 → `MAAuxOutput[id−18]` | `ChooseOutputBusAndChannelIndex @0x6dcee` |
| Output pair 1..10 | 1..7 → `MAOutput` pair; 8..9 → `MAHeadphone` pair `p−7` (**8 = phones 1, 9 = phones 2**); 10 → `MAAuxOutput` pair 1 | `ChooseOutputBusAndChannelPair @0x6dc08`; `MapOutputChannelPairToChannelIDs @0x5c6d0` |

Order inside the groups (which strip owns which pair): output pairs 1–2 analog 1/2, 3/4; pair 3 S/PDIF, pairs 4–7 ADAT — **consistent with** the clone's peak maps (`FWSamples.cpp` `kPeakMap8/12`: analog 0–3, S/PDIF 4–5, ADAT 6–13, ported from `_Sample1814Peaks*`) and with the kext's 14-output device table; the panel code itself does not name the pairs. Input pairs: 1–4 analog, then S/PDIF and ADAT pairs — **inferred** (Q-MAMAP row 24 layout); the per-strip pair assignment lives in the PPob layouts (3051..3054, `panel-rsrc.txt`, raw hex) and was not decoded.
**Note for the clone kext:** the panel addresses up to 14 output channels and 14 SW-return channels; our kext groups are `<4>`/`<4>` (`ConcreteChannelGroup::ChannelAtIndex` clamps out-of-range to 0, `FWChannelGroup.h:81`). The visible UI only writes pairs that have controls (1/2 out, 3/4 out; sw rtn 1–4), so this does not bite, but writes for pairs 3..7 of `MAOutput*` would hit channel 0 — **to review in the integrated run**.

## 2. Rotary mask (`MARotaryControlV2`, closes item 1)
- Preset table read from the binary (`PN2MemDump`, `8CXDevice` symbol +0x10, 8-byte little-endian entries): cookie `0x5e5` value 1..5 → mask
  1 = `0x000000000000FFFF` (SW return), 2 = `0x0000FFFF00000000` (output), 3 = `0x00000000FFFF0000` (input), 4 = `0x0300000000000000` (headphone), 5 = `0x0004000000000000` (aux output).
- Bit layout: **bits 0–15 SW-return pairs (pair p = bit p−1), 16–31 input pairs (bit 15+p), 32–47 output pairs (bit 31+p), bit 50 aux-output pair, bits 56–57 headphone pairs.** Matches the kext bases in Q-MAMAP row 30 (SW 0, input 0x10, output 0x20, aux 0x32, headphone 0x38) and the factory default `0xFFFF00000000` (output group). Evidence: `ReceiveRotaryControlAssignments @0x713d8`, `ChooseRotaryPairPhaseAndBitIndex @0x6fc64`, `SetHWIndexedSetting` cases `0x5ed`/`0x5f7`.
- Per-strip `ctrl` write: cookie `0x5ed` (mixer pairs) / `0x5f7` (output pairs 1..7): read-modify-write of one bit of the 64-bit mask (set when the button value ≠ 0).
- **Mapping of the four sidebar radios** to the five presets: sw rtn → 1, output → 2, input → 3, aux send → 5 (aux output pair), preset 4 (headphone) has no radio in the screenshots — **inferred** from the user's statement that the aux-send group is the aux out bus (P12 item 7) and the screenshots; the code does not name the radios. The panel's per-strip `ctrl` toggling covers output pairs 1..7 and mixer pairs 1..16 only; how the aux strip's `ctrl` sets bit 50 was not found — **unverified**.

## 3. Ranges and scales (closes item 2)
`CXDevice::GetHWSettingRange @0x6e200` (bit masks over `cookie−0x5e8`): cookies `0x5e8, 0x5e9, 0x5f2, 0x5f3` range −64..0 ×1.0 (peak meters, dB); `0x5ea` (aux send), `0x5ec` (mixer levels), `0x5f4` (output levels) range **−129..0, multiplier 0.5** (half-dB steps); `0x5eb` (input pan) and `0x5f5` (aux-out pan) range **−255..+255, multiplier 0.5**. So **pan display = value × 0.5 → "L127 … R127"** matches the screenshots, hard L/R = ∓255 matches the kext default `{-255,+255}` (Q-MAMAP row 23). The panel limits faders to −129 while the kext clamps at −255. Wire half-word order of `MAInputPan2` is a kext-side question and stays **unverified** (needs a live write capture or FFADO/Rust cross-read). The translator writes the value unscaled (`SetChannelLevelProperty @0x6d9c2` replaces array element `idx−1`).

## 4. Aux send and monitor-aux (closes item 3)
- `MAAuxSendLevels`: cookie `0x5ea`, `SetChannelLevelProperty(key, idx)` direct (not bus-rewritten): element `idx−1` with `idx` = the strip's mixer channel id (aux L = odd id, aux R = even id of its pair). 22 elements = 18 inputs + SW-return 1..4 — the 22 is the kext group size; the SW-return half is **inferred**.
- `MAMonitorAuxOnOutput`: cookie `0x5fb`, **index is the output pair 1..10** (count `= outputs/2`, `0x5fb` guards `idx ≤ vt[0x68]/2`); written `value != 1` (panel value 2 = aux, 1 = main), read back `2 − (v == 0)`. The toggle under `1/2 out` is pair 1, `3/4 out` pair 2, the S/PDIF-out strip pair 3 (inferred from §1 order).
- **Correction (2026-10-16):** `PN2-control-key-map.md` §3 and Q-MAMAP row 22 said 10 elements are "per output"; they are per output **pair**. **Second correction (same day, conformance check):** the kext array has **3** elements, not 10 (`FWSettingsAuxSend::Init(..., (output.Count() >> 1) + 1)` in the reference, `FWMixer.cpp:28` in the clone: output pair 1, pair 2 and the S/PDIF pair). The 10 is only the panel translator's index bound (`GetNumberOfAuxMonitorSwitchChannels` = 20 outputs / 2). The panel UI only writes pairs 1-3 (1/2 out, 3/4 out, S/PDIF out).

## 5. Headphone, A/B switch and sheet cookies

> **Correction (2026-10-16, hardware run, R55):** the kernel indexes `MAMomentarySwitchRoutings` by the A/B mode (`SetMomentarySwitchRoutingSource`: idx-1 == fMode; fMode 0 = A, 1 = B), and its default `{1,2,3,4}` is A = out 1/2, B = out 3/4 (the user's expected default). The clone panel therefore reads/writes entries 0/1. How the reference panel's 6-byte cookie 0x609 maps onto that (the "mainMix" word below) stays **unverified**. (closes item 5, corrects P5/P11)
- `CXSelectorHPDevice::SetHWIndexedSetting @0x73c64`, cookie `0x5fd`, 2-byte value: **index 8 (phones 1) → `MAHeadphoneSourceV2`, otherwise (index 9, phones 2) → `MAHeadphoneSecondSource`**, value = `1 << (translate(v)−1)`, `translate(v) = v − (v == 4)` on the FW1814 (`CX1814Device::TranslateHPRoutingPairsForBitConversion @0x72e8e`). Panel values 1/2/4 (P11) therefore become masks **1 / 2 / 4** (out 1/2, out 3/4, aux).
- Non-indexed `0x5fd` → `MAHeadphoneSourceV2` (phones 1). Cookie **`0x609`** (6 bytes = three u16, P11) → `MAMomentarySwitchRoutings` = **NSArray of 3 masks**, `1 << (translate(u16[i])−1)` for i = 0,1,2 (`@0x73906`). Entries 1 and 2 are the A and B sources per P11; entry 0 is the preserved "mainMix" word. **Unverified:** which kernel mode index (`fMode` 0/1/2) the entries address, and how the kext handles a 3-entry write into its 4-entry array (default `{1,2,3,4}`) — check in the integrated run / `FWSettingsABSwitch` (`FWSettings.cpp:361-365`).
- Cookie **`0x608`** → `MAMomentarySwitchSource = (value == 3)`. **Correction (2026-10-16) to P5:** the "MOM group" (`0x14b5`, cookie `0x608`) is the **Momentary switch** (a/b function radios), not `MAMonitorAuxOnOutput`; value 3 → source 1 (the kext's non-headphone, direct-monitoring mode), value 1 → source 0 (headphone A/B). Which of the two radios carries 3 is the panel's resource order — **unverified**, see `HardwareTab` build.

## 6. Peak slots (closes item 4)
The strip → peak mapping is the same identity pair map (`UpdateMixerPairPeakLevels @0xde4ec` calls `GetMixerPairChannelMap(pair)` on the settings object = `MapMixerChannelPairToChannelIDs`, then reads `levels[id−1]`; outputs via `MapOutputChannelPairToChannelIDs`, `COutputView::UpdateOutputPairPeakLevels @0xe1d32`). With P9's shm layout (52 slots = 18 inputs + 20 outputs + 14 SW returns): **input channel id n ↔ `peak[n−1]`; output channel id n ↔ `peak[18+n−1]`; SW-return channel k (mixer id 18+k) ↔ `peak[38+k−1]`**; panel values are dB, floor −64. **Correction (2026-10-16):** P9 §7.3's name `GetMixerPairChannelMap` for "CMiddleWareDevice vt+0x1c" is wrong: `CX1814Device vt[+0x1c]` is `GetNumberOfMixerChannels`; the pair map belongs to `CFW1814DeviceSettings`.

## 6a. Peak dB constants, balance rule, About tab (added 2026-10-16 while building the panel)
- **Peak -> dB** (`CXDevice::GetHWSetting` cookies 0x5e9/0x5f3): raw 0 -> -64, else `ceil(20 * log10(raw * 2^-15))`. Constants read from the panel binary data (`PN2MemDump @000f8b40`): `0xf8b40` = 2^-15, `0xf8b48` = 20.0. raw 32768 (full-scale 16-bit peak) = 0 dB. Non-zero values are not clamped by the reference; the clone clamps at -64 (no visible difference).
- **Balance rule** (`CFW1814DeviceSettings::SetSettingData` cookie 0x5f6, pairs 1, 2 and 8..10): there is no balance key. The panel keeps `base = max(levelL, levelR)` and writes both channel levels through cookie 0x5f4: balance < 0 (left) lowers R to `base + balance`, balance > 0 lowers L to `base - balance`, floor -129. Balance shown = `(levelR - levelL)` (`CalculateOutputPairBalanceLevel @0x5a134`). With **link off** a single fader drag therefore also moves the balance (screenshot `R35`).
- **Routing masks** (cookie 0x5f1, `SetHWIndexedSetting`): the panel sends N destination flags; bit i of the pair's element = destination i (0 = out 1/2, 1 = out 3/4); the element is rebuilt from the flags (other bits are cleared, as in the reference). Element index = mixer pair (inputs) or SW pair (`MASWReturnRoutingV2`, pairs 10..16 -> 1..7).
- **About tab** (`CAboutView::AdaptUIElementsToSettings @0xcda5a`): bootloader = cookie 0x5de, firmware = 0x5e0, hardware = 0x5df ("model %d version %d"), GUID = 0x5e1; the dates come from the `MAFirmwareInfo` block (A1 Q-P3 §3): firmware date/time at 0x20/0x28, bootloader at 0x40/0x48, model/revision at 0x18/0x1C, GUID at 0x10 (two little-endian quadlets, vendor part first), printed as `YYYY-MM-DD HH:MM:SS` + local `%z` (`CalendarDateFromFirmwareDate @0x6f2c0`). Web links come from the panel resources: `http://www.m-audio.com/drivers`, `/support`, `/faq` (`panel-rsrc.txt`; which button opens which URL is unverified). Byte order of the quadlets in the raw block is **unverified** (kext does not swap); the clone decoder prefers big-endian with a little-endian fallback.
- **Sheet rule** (screenshots 11.39.31 / 11.39.49 PM): the source held by the other side is disabled, Aux included.
